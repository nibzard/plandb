# Phase 15.3: Cloud Provider Adapters for NorthstarDB

## Purpose

Cloud provider adapters enable NorthstarDB to store backups, snapshots, and WAL archives in cloud storage services (AWS S3, Google Cloud Storage, Azure Blob Storage). This provides:

- **Geographic redundancy**: Store backups across regions for disaster recovery
- **Unlimited storage**: Offload backup storage from local disk
- **Cross-region replication**: Enable global database distribution
- **Cloud-native deployments**: Support managed database service patterns

## Types

### CloudStorageProvider

**Description**: Enumeration of supported cloud storage providers

**Variants**:
- `AwsS3` - Amazon S3 or S3-compatible storage (MinIO, Wasabi, etc.)
- `Gcs` - Google Cloud Storage
- `AzureBlob` - Azure Blob Storage
- `Local` - Local filesystem (for testing and hybrid deployments)

**Invariants**: Each provider has a corresponding adapter implementation

### S3Config

**Description**: Configuration for AWS S3 or S3-compatible storage

**Fields**:
- `region: String` - AWS region (e.g., "us-east-1", "eu-west-1")
- `bucket: String` - S3 bucket name
- `key_prefix: Option<String>` - Optional key prefix for namespacing (e.g., "northstar/backups/")
- `endpoint: Option<String>` - Custom endpoint for S3-compatible storage (MinIO, Wasabi)
- `access_key_id: String` - AWS access key ID
- `secret_access_key: String` - AWS secret access key
- `session_token: Option<String>` - Temporary session token for IAM roles
- `max_retries: u32` - Maximum retry attempts (default: 3)
- `timeout_secs: u64` - Request timeout in seconds (default: 30)
- `use_path_style: bool` - Use path-style addressing (true for MinIO)

**Size**: 128 bytes + string allocations

**Invariants**:
- `bucket` must be a valid S3 bucket name (DNS-compliant, 3-63 chars)
- `region` must be a valid AWS region identifier
- `access_key_id` and `secret_access_key` must not be empty when not using IAM roles

### GcsConfig

**Description**: Configuration for Google Cloud Storage

**Fields**:
- `bucket: String` - GCS bucket name
- `key_prefix: Option<String>` - Optional key prefix for namespacing
- `credentials_path: Option<String>` - Path to service account JSON credentials file
- `credentials_json: Option<String>` - Inline service account credentials JSON
- `oauth_token: Option<String>` - OAuth2 bearer token (for testing)
- `max_retries: u32` - Maximum retry attempts (default: 3)
- `timeout_secs: u64` - Request timeout in seconds (default: 30)

**Size**: 96 bytes + string allocations

**Invariants**:
- `bucket` must be a valid GCS bucket name
- Either `credentials_path`, `credentials_json`, or `oauth_token` must be provided
- Credentials must have `storage.objects` read/write permissions

### AzureConfig

**Description**: Configuration for Azure Blob Storage

**Fields**:
- `storage_account: String` - Azure storage account name
- `container: String` - Blob container name
- `key_prefix: Option<String>` - Optional key prefix for namespacing
- `access_key: String` - Storage account access key
- `sas_token: Option<String>` - Shared Access Signature token
- `endpoint: Option<String>` - Custom endpoint (default: *.blob.core.windows.net)
- `max_retries: u32` - Maximum retry attempts (default: 3)
- `timeout_secs: u64` - Request timeout in seconds (default: 30)

**Size**: 112 bytes + string allocations

**Invariants**:
- `storage_account` must be a valid Azure storage account name (3-24 chars, alphanumeric)
- `container` must be a valid container name (lowercase, 3-63 chars)
- Either `access_key` or `sas_token` must be provided

### CloudStorageConfig

**Description**: Unified configuration for any cloud storage provider

**Fields**:
- `provider: CloudStorageProvider` - Which cloud provider to use
- `s3: Option<S3Config>` - S3 configuration (required when provider is AwsS3)
- `gcs: Option<GcsConfig>` - GCS configuration (required when provider is Gcs)
- `azure: Option<AzureConfig>` - Azure configuration (required when provider is Azure)
- `upload_part_size_mb: usize` - Multipart upload part size in MB (default: 16)
- `max_concurrent_uploads: usize` - Maximum concurrent upload threads (default: 4)
- `download_part_size_mb: usize` - Download buffer size in MB (default: 16)

**Size**: 248 bytes

**Invariants**:
- Configuration must match the selected provider (e.g., if provider is AwsS3, s3 must be Some)
- `upload_part_size_mb` must be >= 5 (S3 minimum) and <= 5000 (S3 maximum)
- `max_concurrent_uploads` must be >= 1 and <= 32

### CloudLocation

**Description**: Represents a specific location in cloud storage

**Fields**:
- `config: CloudStorageConfig` - Provider and connection configuration
- `key: String` - Storage key/object name within bucket/container
- `version_id: Option<String>` - Object version (for versioned buckets)

**Size**: 264 bytes + string allocations

**Invariants**:
- `key` must be a valid object key (URL-encoded if necessary)
- Keys should use forward slash separators for hierarchical organization

### CloudUploadProgress

**Description**: Progress tracking for ongoing uploads

**Fields**:
- `bytes_uploaded: u64` - Total bytes uploaded so far
- `total_bytes: u64` - Total bytes to upload (None if unknown)
- `parts_completed: usize` - Number of multipart parts completed
- `total_parts: usize` - Total number of parts (for multipart uploads)
- `started_at: chrono::DateTime<chrono::Utc>` - Upload start time
- `current_part_bytes: u64` - Bytes uploaded in current part

**Size**: 56 bytes + timestamp

**Invariants**:
- `bytes_uploaded` <= `total_bytes` (when total_bytes is Some)
- `parts_completed` <= `total_parts`

### CloudDownloadProgress

**Description**: Progress tracking for ongoing downloads

**Fields**:
- `bytes_downloaded: u64` - Total bytes downloaded so far
- `total_bytes: u64` - Total bytes to download (None if unknown)
- `started_at: chrono::DateTime<chrono::Utc>` - Download start time
- `current_part_bytes: u64` - Bytes downloaded in current chunk

**Size**: 48 bytes + timestamp

**Invariants**:
- `bytes_downloaded` <= `total_bytes` (when total_bytes is Some)

### CloudBackupMetadata

**Description**: Extended backup metadata for cloud-stored backups

**Fields**:
- `backup: Backup` - Base backup metadata (from recovery module)
- `cloud_location: CloudLocation` - Where the backup is stored in cloud
- `storage_class: Option<String>` - Storage class (e.g., "STANDARD", "GLACIER", "ARCHIVE")
- `etag: Option<String>` - ETag of uploaded object (for integrity verification)
- `version_id: Option<String>` - Object version ID (for versioned buckets)
- `upload_cost_usd: Option<f64>` - Estimated upload cost in USD
- `storage_cost_per_month_usd: Option<f64>` - Estimated monthly storage cost

**Size**: 352 bytes + string allocations

**Invariants**:
- `backup.id` must match a key in the cloud storage
- `storage_class` must be valid for the selected provider

### CloudError

**Description**: Cloud storage operation errors

**Variants**:
- `AuthenticationFailed` - Invalid credentials or token expired
- `BucketNotFound` - Bucket/container does not exist or no access
- `ObjectNotFound` - Requested object key does not exist
- `PermissionDenied` - Insufficient permissions for operation
- `QuotaExceeded` - Storage quota or request rate limit exceeded
- `NetworkError` - Network connectivity or DNS resolution failure
- `Timeout` - Operation exceeded configured timeout
- `InvalidRequest` - Malformed request or invalid parameters
- `ChecksumMismatch` - Downloaded data checksum does not match expected
- `UploadCancelled` - Upload was cancelled before completion
- `Other(String)` - Provider-specific error

**Invariants**: Error context should include enough detail to diagnose and retry

## Functions

### CloudStorageAdapter::new(config: CloudStorageConfig) -> Result<Self>

**Purpose**: Create a new cloud storage adapter with the given configuration

**Parameters**:
- `config: CloudStorageConfig` - Provider configuration and connection settings

**Returns**: `Result<CloudStorageAdapter>` - Initialized adapter or error

**Algorithm**:
1. Validate configuration matches selected provider
2. Create provider-specific client (AWS SDK, Google Cloud client, Azure SDK)
3. Test connectivity with a lightweight operation (e.g., list bucket)
4. Return configured adapter on success

**Error Conditions**:
- `CloudError::InvalidRequest` - Configuration is missing required fields
- `CloudError::AuthenticationFailed` - Invalid credentials
- `CloudError::NetworkError` - Cannot reach cloud service endpoint

**Concurrency**: Safe to share across threads (Arc<RwLock<>>)

### CloudStorageAdapter::upload(&self, key: &str, data: &[u8], progress: Option<ProgressBar>) -> Result<String>

**Purpose**: Upload a single object to cloud storage

**Parameters**:
- `key: &str` - Object key/name in bucket
- `data: &[u8]` - Data to upload
- `progress: Option<ProgressBar>` - Optional progress callback

**Returns**: `Result<String>` - ETag or version ID of uploaded object

**Algorithm**:
1. If data size > 100MB, use multipart upload (see upload_multipart)
2. Calculate SHA-256 checksum of data
3. Initiate upload to configured provider
4. Send data in chunks (using configured chunk size)
5. Verify upload completed successfully
6. Return object ETag or version ID

**Error Conditions**:
- `CloudError::QuotaExceeded` - Bucket size limit reached
- `CloudError::PermissionDenied` - No write permission
- `CloudError::NetworkError` - Upload failed due to network issues
- `CloudError::UploadCancelled` - Upload was cancelled

**Concurrency**: Multiple concurrent uploads allowed (per-provider limits apply)

### CloudStorageAdapter::upload_multipart(&self, key: &str, data: &[u8], progress: Option<ProgressBar>) -> Result<String>

**Purpose**: Upload large objects using multipart upload API

**Parameters**:
- `key: &str` - Object key/name in bucket
- `data: &[u8]` - Data to upload (typically > 100MB)
- `progress: Option<ProgressBar>` - Optional progress callback

**Returns**: `Result<String>` - ETag of completed multipart upload

**Algorithm**:
1. Split data into parts of configured size (default 16MB)
2. Initiate multipart upload session with provider
3. For each part:
   a. Upload part in parallel (respecting max_concurrent_uploads limit)
   b. Track part ETag returned by provider
   c. Update progress callback
4. After all parts uploaded, complete multipart upload with part ETags list
5. Return final object ETag

**Error Conditions**:
- `CloudError::NetworkError` - One or more parts failed to upload
- `CloudError::Timeout` - Upload exceeded timeout
- `CloudError::UploadCancelled` - Upload was cancelled

**Concurrency**: Uploads parts in parallel thread pool

### CloudStorageAdapter::download(&self, key: &str, progress: Option<ProgressBar>) -> Result<Vec<u8>>

**Purpose**: Download a single object from cloud storage

**Parameters**:
- `key: &str` - Object key/name in bucket
- `progress: Option<ProgressBar>` - Optional progress callback

**Returns**: `Result<Vec<u8>>` - Downloaded data

**Algorithm**:
1. Request object metadata from provider (size, ETag)
2. If object > 100MB, use multipart download
3. Download data in chunks (using configured chunk size)
4. Calculate SHA-256 checksum of downloaded data
5. Verify checksum matches expected (if ETag is checksum-based)
6. Return data on success

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist in bucket
- `CloudError::PermissionDenied` - No read permission
- `CloudError::ChecksumMismatch` - Downloaded data corrupted
- `CloudError::NetworkError` - Download failed

**Concurrency**: Multiple concurrent downloads allowed

### CloudStorageAdapter::delete(&self, key: &str) -> Result<()>

**Purpose**: Delete a single object from cloud storage

**Parameters**:
- `key: &str` - Object key/name to delete

**Returns**: `Result<()>` - Success or error

**Algorithm**:
1. Send delete request to provider
2. Verify deletion completed
3. Return success

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist (may be OK)
- `CloudError::PermissionDenied` - No delete permission

**Concurrency**: Safe to call concurrently for different keys

### CloudStorageAdapter::exists(&self, key: &str) -> Result<bool>

**Purpose**: Check if an object exists in cloud storage

**Parameters**:
- `key: &str` - Object key/name to check

**Returns**: `Result<bool>` - True if exists, false if not

**Algorithm**:
1. Send HEAD or metadata request to provider
2. Return true if object exists, false if not found
3. Return error for other failures

**Error Conditions**:
- `CloudError::PermissionDenied` - No read permission

**Concurrency**: Safe to call concurrently

### CloudStorageAdapter::list(&self, prefix: &str) -> Result<Vec<String>>

**Purpose**: List all objects with a given prefix

**Parameters**:
- `prefix: &str` - Key prefix to filter (e.g., "backups/2026-01-")

**Returns**: `Result<Vec<String>>` - List of object keys

**Algorithm**:
1. Send list request with prefix filter to provider
2. Paginate through results if provider returns >1000 objects
3. Collect all matching keys
4. Return sorted list

**Error Conditions**:
- `CloudError::PermissionDenied` - No list permission

**Concurrency**: Safe to call concurrently

### CloudStorageAdapter::get_object_size(&self, key: &str) -> Result<u64>

**Purpose**: Get size of an object without downloading it

**Parameters**:
- `key: &str` - Object key/name

**Returns**: `Result<u64>` - Size in bytes

**Algorithm**:
1. Request object metadata from provider
2. Extract size field
3. Return size

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist

**Concurrency**: Safe to call concurrently

### S3Adapter::upload_part(&self, upload_id: &str, part_number: u32, data: &[u8]) -> Result<String>

**Purpose**: Upload a single part of a multipart upload (S3-specific)

**Parameters**:
- `upload_id: &str` - Multipart upload session ID
- `part_number: u32` - Part number (1-indexed)
- `data: &[u8]` - Part data

**Returns**: `Result<String>` - Part ETag

**Algorithm**:
1. Send PUT request to S3 with upload ID and part number
2. Retry on transient errors (up to max_retries)
3. Return ETag from response

**Error Conditions**:
- `CloudError::NetworkError` - Upload failed after retries
- `CloudError::InvalidRequest` - Invalid part number or upload_id

**Concurrency**: Safe to upload multiple parts in parallel

### S3Adapter::complete_multipart_upload(&self, key: &str, upload_id: &str, parts: Vec<(u32, String)>) -> Result<String>

**Purpose**: Complete a multipart upload by combining all parts

**Parameters**:
- `key: &str` - Object key
- `upload_id: &str` - Multipart upload session ID
- `parts: Vec<(u32, String)>` - List of (part_number, ETag) tuples

**Returns**: `Result<String>` - Final object ETag

**Algorithm**:
1. Send CompleteMultipartUpload request to S3
2. S3 combines parts in order
3. Return final object ETag

**Error Conditions**:
- `CloudError::InvalidRequest` - Parts list is incomplete or invalid

**Concurrency**: Must be called after all parts uploaded

### CloudBackupManager::new(adapter: Arc<CloudStorageAdapter>, backup_manager: Arc<BackupManager>) -> Self

**Purpose**: Create a cloud-aware backup manager that extends local backup functionality

**Parameters**:
- `adapter: Arc<CloudStorageAdapter>` - Cloud storage adapter
- `backup_manager: Arc<BackupManager>` - Local backup manager from recovery module

**Returns**: `CloudBackupManager` - New instance

**Algorithm**:
1. Store adapter and backup_manager references
2. Initialize upload thread pool (max_concurrent_uploads workers)
3. Return manager

**Error Conditions**: None (constructor)

**Concurrency**: Manager is thread-safe

### CloudBackupManager::upload_backup_to_cloud(&self, backup_id: Uuid, progress: Option<ProgressBar>) -> Result<CloudBackupMetadata>

**Purpose**: Upload a local backup to cloud storage

**Parameters**:
- `backup_id: Uuid` - ID of local backup to upload
- `progress: Option<ProgressBar>` - Optional progress callback

**Returns**: `Result<CloudBackupMetadata>` - Cloud backup metadata

**Algorithm**:
1. Get local backup metadata from BackupManager
2. Read backup file data from local disk
3. Generate cloud key: "backups/{year}/{month}/{backup_id}.nbk"
4. Upload backup file to cloud using adapter
5. Create CloudBackupMetadata with ETag, version ID, cost estimates
6. Return metadata

**Error Conditions**:
- `DbError::BackupNotFound` - Local backup does not exist
- `CloudError::NetworkError` - Upload failed
- `CloudError::QuotaExceeded` - Cloud storage quota exceeded

**Concurrency**: Safe to call concurrently (multiple backups can upload in parallel)

### CloudBackupManager::download_backup_from_cloud(&self, cloud_location: &CloudLocation, progress: Option<ProgressBar>) -> Result<Backup>

**Purpose**: Download a cloud backup and register it locally

**Parameters**:
- `cloud_location: &CloudLocation` - Cloud backup location
- `progress: Option<ProgressBar>` - Optional progress callback

**Returns**: `Result<Backup>` - Local backup metadata

**Algorithm**:
1. Download backup file from cloud using adapter
2. Verify SHA-256 checksum
3. Write to local backup directory
4. Register with local BackupManager
5. Return local backup metadata

**Error Conditions**:
- `CloudError::ObjectNotFound` - Backup not found in cloud
- `CloudError::ChecksumMismatch` - Downloaded data corrupted

**Concurrency**: Safe to call concurrently

### CloudBackupManager::list_cloud_backups(&self, prefix: Option<&str>) -> Result<Vec<CloudBackupMetadata>>

**Purpose**: List all backups stored in cloud

**Parameters**:
- `prefix: Option<&str>` - Optional key prefix filter (e.g., "backups/2026/")

**Returns**: `Result<Vec<CloudBackupMetadata>>` - List of cloud backups

**Algorithm**:
1. List all objects with "backups/" prefix
2. For each object:
   a. Read metadata (size, ETag, last modified)
   b. Parse backup ID from key
   c. Create CloudBackupMetadata stub
3. Return sorted list (newest first)

**Error Conditions**:
- `CloudError::PermissionDenied` - No list permission
- `CloudError::NetworkError` - List operation failed

**Concurrency**: Safe to call concurrently

### CloudBackupManager::delete_cloud_backup(&self, cloud_location: &CloudLocation) -> Result<()>

**Purpose**: Delete a backup from cloud storage

**Parameters**:
- `cloud_location: &CloudLocation` - Cloud backup location

**Returns**: `Result<()>` - Success or error

**Algorithm**:
1. Delete object from cloud using adapter
2. Optionally delete local copy if present
3. Return success

**Error Conditions**:
- `CloudError::ObjectNotFound` - Backup not found (may be OK)
- `CloudError::PermissionDenied` - No delete permission

**Concurrency**: Safe to call concurrently

### CloudBackupManager::sync_backups_to_cloud(&self, retention: &BackupRetentionPolicy) -> Result<SyncReport>

**Purpose**: Sync local backups to cloud and apply retention policy

**Parameters**:
- `retention: &BackupRetentionPolicy` - Retention policy for cloud backups

**Returns**: `Result<SyncReport>` - Sync operation report

**Algorithm**:
1. List all local backups from BackupManager
2. List all cloud backups
3. Upload local backups not in cloud
4. Delete cloud backups exceeding retention policy
5. Generate sync report (uploaded, deleted, failed counts)
6. Return report

**Error Conditions**:
- `CloudError::NetworkError` - Partial sync failure
- `CloudError::QuotaExceeded` - Cannot upload due to quota

**Concurrency**: Should be called exclusively (one sync at a time)

### CloudBackupManager::estimate_cost(&self, storage_class: &str, size_mb: u64) -> CostEstimate

**Purpose**: Estimate storage costs for a backup

**Parameters**:
- `storage_class: &str` - Storage class ("STANDARD", "GLACIER", etc.)
- `size_mb: u64` - Backup size in MB

**Returns**: `CostEstimate` - Cost breakdown

**Algorithm**:
1. Look up provider pricing (S3/GCS/Azure current rates)
2. Calculate monthly storage cost based on size and class
3. Calculate request costs (PUT, GET, LIST operations)
4. Calculate data transfer costs (if applicable)
5. Return cost estimate

**Concurrency**: Safe to call concurrently

## Invariants

- **Cloud storage keys use forward slash separators**: All keys use "/" for hierarchy (Windows-style "\" is not allowed)
- **Uploads are atomic**: Either complete successfully or leave no partial data
- **ETags are verified**: After upload, ETag is stored for later integrity verification
- **Retries are exponential**: Failed requests retry with exponential backoff (1s, 2s, 4s, 8s, ...)
- **Credentials are never logged**: Credentials and tokens are excluded from logs and error messages
- **Progress callbacks are optional**: All operations work without progress tracking
- **Multipart uploads have minimum part size**: Each part >= 5MB (S3 requirement)
- **Concurrent uploads are bounded**: Never exceed max_concurrent_uploads limit

## Rust Implementation Guidance

### Module Structure

```
northstar-core/src/cloud/
├── mod.rs              # Module exports and CloudStorageAdapter trait
├── s3.rs               # AWS S3 adapter implementation
├── gcs.rs              # Google Cloud Storage adapter
├── azure.rs            # Azure Blob Storage adapter
├── backup.rs           # CloudBackupManager (extends recovery::backup)
└── cost.rs             # Cost estimation utilities
```

### Type Definitions

- **CloudStorageAdapter**: Trait object with `Arc<RwLock<dyn CloudStorageAdapter>>` for runtime provider selection
- **S3Adapter**: Uses `rusoto_s3` or `aws_sdk_s3` crate
- **GcsAdapter**: Uses `google-cloud-storage` crate
- **AzureAdapter**: Uses `azure_storage` crate

### External Dependencies

Add to `northstar-core/Cargo.toml`:
```toml
# AWS SDK (feature-gated)
aws-config = { version = "1.0", optional = true }
aws-sdk-s3 = { version = "1.0", optional = true }

# Google Cloud (feature-gated)
google-cloud-storage = { version = "0.1", optional = true }
google-cloud-auth = { version = "0.1", optional = true }

# Azure (feature-gated)
azure_storage = { version = "0.20", optional = true }
azure_identity = { version = "0.20", optional = true }

# For async runtime
tokio = { version = "1", features = ["full"] }
async-trait = "0.1"

# Progress reporting
indicatif = "0.17"
```

### Feature Flags

```toml
[features]

```

### Concurrency

- **Pattern**: Use `Arc<RwLock<dyn CloudStorageAdapter>>` for shared adapter
- **Pattern**: Use `tokio::spawn` for concurrent multipart uploads
- **Pattern**: Use `Semaphore` to bound concurrent operations

### Key Decisions

- **rusoto vs aws-sdk-s3**: Use `aws-sdk-s3` (modern, maintained, has async support)
- **Sync vs Async**: Use async/await with Tokio (all cloud SDKs are async)
- **Unified Error Type**: Convert provider-specific errors to `CloudError`
- **Progress Callback**: Use `indicatif::ProgressBar` for CLI, optional callback for API

### Implementation Notes

1. **Credential Loading**:
   - S3: Support environment variables, ~/.aws/credentials, IAM role
   - GCS: Support GOOGLE_APPLICATION_CREDENTIALS env var
   - Azure: Support AZURE_STORAGE_KEY env var

2. **Multipart Upload**:
   - Initiate upload → Upload parts (parallel) → Complete upload
   - Track part ETags in memory
   - Abort upload on error (clean up partial uploads)

3. **Retry Logic**:
   - Use `tokio::time::sleep` for exponential backoff
   - Retry on: 5xx errors, network timeouts, rate limit (429)
   - Don't retry on: 4xx errors (except 429)

4. **Cost Estimation**:
   - Hard-code current pricing (update periodically)
   - Or fetch pricing API if available (AWS Price List API)

### Testing Strategy

**Unit tests needed for**:
- Key generation and formatting
- Cost estimation calculations
- Configuration validation
- Error mapping from provider errors

**Integration tests for**:
- Upload/download roundtrip (local → cloud → local)
- Multipart upload with 100MB+ files
- List and filter operations
- Delete and exists operations
- Retry logic with simulated failures

**Testing against local services**:
- S3: Use MinIO or LocalStack
- GCS: Use fake-gcs-server
- Azure: Use Azurite

**Mock testing**:
- Use `mockito` or `wiremock` to mock HTTP endpoints
- Test retry logic and error handling without real cloud costs

### Security Considerations

- **Credential storage**: Never hardcode credentials in code
- **Encryption**: Use HTTPS for all cloud API calls
- **Secrets logging**: Exclude credentials from logs and error messages
- **IAM roles**: Prefer IAM roles over access keys when possible
- **Bucket policies**: Document required IAM permissions for bucket

### Performance Targets

- Upload throughput: >50 MB/s (depends on network)
- Download throughput: >100 MB/s (depends on network)
- Multipart upload overhead: <5% (vs single-part)
- List 1000 objects: <2 seconds
