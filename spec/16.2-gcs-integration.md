# Phase 16.2: Google Cloud Storage Integration for NorthstarDB

## Purpose

Phase 16.2 implements production-ready Google Cloud Storage (GCS) integration using the official Google Cloud Rust crates. This enables NorthstarDB to store backups, snapshots, and WAL archives in Google Cloud Storage with:

- **Automatic credential management**: Service account keys, Application Default Credentials (ADC), Workload Identity
- **Streaming operations**: Efficient upload/download without buffering entire files
- **Resumable uploads**: Large file uploads with automatic retry on network failures
- **Retry logic**: Exponential backoff for transient failures
- **Compatibility**: Support for GCS emulator (local development and testing)

This phase replaces the placeholder GcsAdapter from Phase 15.3 with a full implementation using google-cloud-storage and related crates.

## Types

### GcsClient

**Description**: GCS client wrapper with NorthstarDB configuration

**Fields**:
- `client: google_cloud_storage::Client` - GCS client
- `config: GcsConfig` - NorthstarDB GCS configuration
- `bucket: String` - Target bucket name
- `key_prefix: Option<String>` - Optional key prefix for namespacing

**Size**: 256 bytes + client overhead

**Invariants**:
- `client` is configured with correct credentials
- `bucket` exists and is accessible
- All operations use configured retry strategy

### ResumableUploadSession

**Description**: Tracks in-progress resumable upload

**Fields**:
- `upload_id: String` - GCS resumable upload session ID
- `key: String` - Object key being uploaded
- `total_bytes: u64` - Total upload size
- `uploaded_bytes: u64` - Bytes uploaded so far
- `chunk_size: usize` - Upload chunk size (default: 256KB)

**Size**: 128 bytes

**Invariants**:
- `uploaded_bytes` <= `total_bytes`
- `chunk_size` is a multiple of 256KB (GCS requirement)

### UploadProgress

**Description**: Progress callback for upload operations

**Signature**: `fn(bytes_uploaded: u64, total_bytes: Option<u64>)`

**Purpose**: Allow caller to track upload progress for UI/monitoring

**Invariants**:
- `total_bytes` is None for streaming uploads (unknown size)
- Callback is invoked after each chunk/part

### DownloadProgress

**Description**: Progress callback for download operations

**Signature**: `fn(bytes_downloaded: u64, total_bytes: Option<u64>)`

**Purpose**: Allow caller to track download progress for UI/monitoring

**Invariants**:
- `total_bytes` is None if object size is unknown
- Callback is invoked after each chunk

## Functions

### GcsAdapter::new(config: CloudStorageConfig) -> Result<Self>

**Purpose**: Create a new GCS adapter with Google Cloud client

**Parameters**:
- `config: CloudStorageConfig` - Cloud configuration with GCS settings

**Returns**: `Result<GcsAdapter>` - Initialized adapter or error

**Algorithm**:
1. Extract GcsConfig from CloudStorageConfig
2. Validate GcsConfig (bucket name)
3. Determine credential source:
   a. If explicit credentials_json provided, parse and use
   b. If explicit credentials_path provided, load from file
   c. If explicit oauth_token provided, use bearer token
   d. Otherwise, use Application Default Credentials (ADC)
4. Create GCS client configuration:
   - Set bucket from GcsConfig
   - Set credentials (service account, OAuth, or ADC)
   - Configure timeout (default 30 seconds)
   - Set retry strategy (max 3 retries, exponential backoff)
5. Build GCS client
6. Test connectivity by checking bucket existence
7. Return GcsAdapter on success

**Error Conditions**:
- `CloudError::InvalidRequest` - Missing or invalid configuration
- `CloudError::AuthenticationFailed` - Invalid credentials
- `CloudError::BucketNotFound` - Bucket does not exist or no access
- `CloudError::NetworkError` - Cannot reach GCS endpoint

**Concurrency**: Safe to share across threads (GCS client is Arc + clone)

### GcsAdapter::upload(&self, key: &str, data: &[u8], progress: Option<UploadProgress>) -> Result<String>

**Purpose**: Upload data to GCS (simple or resumable)

**Parameters**:
- `key: &str` - Object key in bucket
- `data: &[u8]` - Data to upload
- `progress: Option<UploadProgress>` - Optional progress callback

**Returns**: `Result<String>` - Object generation ID (version)

**Algorithm**:
1. Apply key_prefix if configured
2. If data.len() > 5MB (5,242,880 bytes), use resumable upload:
   - Call upload_resumable() method
3. Else, use simple upload:
   - Create UploadObjectRequest with data as byte buffer
   - Set content type (application/octet-stream)
   - Invoke GCS client upload() operation
   - Await response
   - Extract generation ID from response
4. Return generation ID

**Error Conditions**:
- `CloudError::QuotaExceeded` - Bucket size limit reached
- `CloudError::PermissionDenied` - No write permission (storage.objects.create)
- `CloudError::NetworkError` - Upload failed after retries
- `CloudError::Timeout` - Upload exceeded timeout

**Concurrency**: Safe to call concurrently (multiple parallel uploads)

### GcsAdapter::upload_resumable(&self, key: &str, data: &[u8], progress: Option<UploadProgress>) -> Result<String>

**Purpose**: Upload large objects using resumable upload API

**Parameters**:
- `key: &str` - Object key in bucket
- `data: &[u8]` - Data to upload (>5MB)
- `progress: Option<UploadProgress>` - Optional progress callback

**Returns**: `Result<String>` - Object generation ID

**Algorithm**:
1. Apply key_prefix if configured
2. Calculate chunk size (256KB or larger, must be multiple of 256KB)
3. Split data into chunks of chunk_size
4. Initiate resumable upload:
   a. Create ResumableUploadRequest with total size
   b. Invoke initiate_resumable_upload() to get upload_id
5. For each chunk:
   a. Calculate byte range (start:end)
   b. Upload chunk with Content-Range header
   c. On 308 (Resume Incomplete), parse Range header to verify progress
   d. On network error, retry with last committed byte offset
   e. Update progress callback
6. On 200 (OK), extract generation ID from response
7. Return generation ID

**Error Conditions**:
- `CloudError::NetworkError` - Upload failed after retries
- `CloudError::Timeout` - Upload exceeded timeout
- `CloudError::UploadCancelled` - Upload was aborted

**Concurrency**: Uploads chunks sequentially (GCS resumable upload requirement)

### GcsAdapter::download(&self, key: &str, progress: Option<DownloadProgress>) -> Result<Vec<u8>>

**Purpose**: Download object from GCS

**Parameters**:
- `key: &str` - Object key in bucket
- `progress: Option<DownloadProgress>` - Optional progress callback

**Returns**: `Result<Vec<u8>>` - Downloaded data

**Algorithm**:
1. Apply key_prefix if configured
2. Create DownloadObjectRequest
3. Invoke download() operation
4. Stream response body to buffer:
   - Read chunks (default 8MB)
   - Accumulate into Vec<u8>
   - Update progress callback
5. Return buffer

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist (404)
- `CloudError::PermissionDenied` - No read permission (storage.objects.get)
- `CloudError::NetworkError` - Download failed after retries

**Concurrency**: Safe to call concurrently (multiple parallel downloads)

### GcsAdapter::delete(&self, key: &str) -> Result<()>

**Purpose**: Delete object from GCS

**Parameters**:
- `key: &str` - Object key to delete

**Returns**: `Result<()>` - Success or error

**Algorithm**:
1. Apply key_prefix if configured
2. Create DeleteObjectRequest
3. Invoke delete() operation
4. Return success

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist (may be OK)
- `CloudError::PermissionDenied` - No delete permission (storage.objects.delete)

**Concurrency**: Safe to call concurrently

### GcsAdapter::exists(&self, key: &str) -> Result<bool>

**Purpose**: Check if object exists in GCS

**Parameters**:
- `key: &str` - Object key to check

**Returns**: `Result<bool>` - True if exists, false if not

**Algorithm**:
1. Apply key_prefix if configured
2. Create GetObjectRequest (metadata-only request)
3. Invoke get_object_metadata() operation
4. Return true if success (200 OK)
5. Return false if NotFound error (404)
6. Return error for other failures

**Error Conditions**:
- `CloudError::PermissionDenied` - No read permission (storage.objects.get)

**Concurrency**: Safe to call concurrently

### GcsAdapter::list(&self, prefix: &str) -> Result<Vec<String>>

**Purpose**: List objects with given prefix

**Parameters**:
- `prefix: &str` - Key prefix to filter (e.g., "backups/2026-01-")

**Returns**: `Result<Vec<String>>` - List of object keys

**Algorithm**:
1. Apply key_prefix if configured
2. Create ListObjectsRequest with prefix
3. Invoke list() operation
4. Collect object keys from response.items
5. While response.next_page_token is present:
   a. Set page_token from response.next_page_token
   b. Invoke list() again
   c. Accumulate more keys
6. Return sorted list

**Error Conditions**:
- `CloudError::PermissionDenied` - No list permission (storage.objects.list)

**Concurrency**: Safe to call concurrently

### GcsAdapter::get_object_size(&self, key: &str) -> Result<u64>

**Purpose**: Get object size without downloading

**Parameters**:
- `key: &str` - Object key

**Returns**: `Result<u64>` - Size in bytes

**Algorithm**:
1. Apply key_prefix if configured
2. Create GetObjectRequest (metadata-only request)
3. Invoke get_object_metadata() operation
4. Extract size from response
5. Return size

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist

**Concurrency**: Safe to call concurrently

### resolve_credentials(config: &GcsConfig) -> Result<Credentials>

**Purpose**: Load GCS credentials from multiple sources

**Parameters**:
- `config: &GcsConfig` - GCS configuration

**Returns**: `Result<Credentials>` - GCS credentials

**Algorithm**:
1. If explicit credentials_json provided:
   - Parse JSON string
   - Create service account credentials from JSON
   - Return credentials
2. If explicit credentials_path provided:
   - Read JSON file from path
   - Create service account credentials from file
   - Return credentials
3. If explicit oauth_token provided:
   - Create OAuth bearer token credentials
   - Return credentials
4. Otherwise, use Application Default Credentials (ADC):
   - Check environment variable `GOOGLE_APPLICATION_CREDENTIALS`
   - Check gcloud default credentials (~/.config/gcloud/application_default_credentials.json)
   - Check metadata server (GCE, GKE, Cloud Run)
   - Return first valid credentials
5. If no valid credentials, return error

**Error Conditions**:
- `CloudError::AuthenticationFailed` - No valid credentials found
- `CloudError::InvalidRequest` - Credentials JSON is malformed

**Concurrency**: Safe to call

### build_retry_strategy(max_retries: u32) -> RetryConfig

**Purpose**: Configure GCS client retry behavior

**Parameters**:
- `max_retries: u32` - Maximum retry attempts

**Returns**: `RetryConfig` - GCS retry configuration

**Algorithm**:
1. Create RetryConfig with max_attempts = max_retries + 1
2. Set backoff strategy to exponential:
   - Initial delay: 1 second
   - Multiplier: 2.0
   - Max delay: 32 seconds (GCS recommendation)
3. Configure retryable errors:
   - Network errors (connection reset, timeout)
   - HTTP 429 (Too Many Requests)
   - HTTP 503 (Service Unavailable)
   - HTTP 502 (Bad Gateway)
4. Return config

**Error Conditions**: None

**Concurrency**: Safe to call

## Invariants

- **Resumable uploads are sequential**: Chunks uploaded in order (GCS requirement)
- **Uploads complete atomically**: Resumable uploads only visible after final 200 OK
- **Generation IDs are returned**: All uploads return generation for versioning
- **Key prefix is applied**: All operations prepend configured key_prefix
- **Credentials are never logged**: Service account keys and tokens excluded from logs/errors
- **Retries are exponential**: Failed requests retry with exponential backoff (1s, 2s, 4s, 8s, ...)
- **Chunk size is aligned**: Resumable upload chunks are multiples of 256KB
- **Streaming is used**: Large files streamed in chunks, not buffered entirely in memory

### Key Implementation Details

1. **GCS Client Creation**:
   ```rust
   use google_cloud_storage::Client;
   use google_cloud_token::TokenProvider;
   use google_cloud_auth::token::DefaultTokenSourceProvider;

   // Load credentials from config or ADC
   let token_provider = if let Some(creds_json) = &gcs_config.credentials_json {
       // Service account from JSON string
       let credentials: ServiceAccountCredentials = serde_json::from_str(creds_json)?;
       TokenProvider::from_service_account(credentials)
   } else if let Some(creds_path) = &gcs_config.credentials_path {
       // Service account from file
       let credentials = ServiceAccountCredentials::from_file(creds_path).await?;
       TokenProvider::from_service_account(credentials)
   } else if let Some(token) = &gcs_config.oauth_token {
       // Bearer token (for testing)
       TokenProvider::from_bearer_token(token.clone())
   } else {
       // Application Default Credentials
       let provider = DefaultTokenSourceProvider::new().await?;
       TokenProvider::from_adc(provider)
   };

   // Build GCS client
   let client = Client::new(
       gcs_config.bucket.clone(),
       token_provider,
       Some(Duration::from_secs(gcs_config.timeout_secs as u64)),
   );
   ```

2. **Simple Upload**:
   ```rust
   use google_cloud_storage::client::UploadObjectRequest;

   let byte_stream = bytes::Bytes::from(data.to_vec());
   let upload_request = UploadObjectRequest {
       bucket: self.bucket.clone(),
       object: full_key.clone(),
       content_type: Some("application/octet-stream".to_string()),
       ..Default::default()
   };

   let response = self.client.upload(&upload_request, byte_stream).await?;

   Ok(response.generation.ok_or_else(|| CloudError::Other("Missing generation".into()))?)
   ```

3. **Resumable Upload**:
   ```rust
   use google_cloud_storage::client::{ResumableUploadRequest, UploadChunkRequest};

   const CHUNK_SIZE: usize = 256 * 1024; // 256KB (GCS requirement)

   // Initiate resumable upload
   let initiate_request = ResumableUploadRequest {
       bucket: self.bucket.clone(),
       object: full_key.clone(),
       size: Some(data.len() as u64),
       content_type: Some("application/octet-stream".to_string()),
       ..Default::default()
   };

   let upload_id = self.client.initiate_resumable_upload(&initiate_request).await?;

   // Upload chunks sequentially
   let mut uploaded_bytes = 0;
   for (i, chunk) in data.chunks(CHUNK_SIZE).enumerate() {
       let chunk_start = uploaded_bytes;
       let chunk_end = uploaded_bytes + chunk.len() as u64 - 1;
       let is_last = chunk_end == (data.len() as u64 - 1);

       let chunk_request = UploadChunkRequest {
           bucket: self.bucket.clone(),
           object: full_key.clone(),
           upload_id: upload_id.clone(),
           chunk: chunk.to_vec(),
           content_range: Some(format!("bytes {}-{}/{}", chunk_start, chunk_end, data.len())),
           is_last,
           ..Default::default()
       };

       let response = self.client.upload_chunk(&chunk_request).await?;

       // On 308 (Resume Incomplete), verify progress
       if response.status() == 308 {
           let range = response.range().ok_or_else(|| CloudError::Other("Missing Range header".into()))?;
           uploaded_bytes = range.1 + 1; // Resume from last byte
       } else if response.status() == 200 {
           // Upload complete
           let generation = response.generation().ok_or_else(|| CloudError::Other("Missing generation".into()))?;
           return Ok(generation.to_string());
       }

       // Update progress callback
       if let Some(cb) = &progress {
           cb(uploaded_bytes, Some(data.len() as u64));
       }

       uploaded_bytes += chunk.len() as u64;
   }

   Err(CloudError::Other("Upload incomplete".into()))
   ```

4. **Streaming Download**:
   ```rust
   use google_cloud_storage::client::DownloadObjectRequest;

   let download_request = DownloadObjectRequest {
       bucket: self.bucket.clone(),
       object: full_key.clone(),
       ..Default::default()
   };

   let response = self.client.download(&download_request).await?;

   let content_length = response.content_length;
   let mut buffer = Vec::with_capacity(content_length);
   let mut stream = response.bytes_stream();

   while let Some(chunk_result) = stream.next().await {
       let chunk = chunk_result.map_err(|e| {
           CloudError::NetworkError(format!("Download stream error: {}", e))
       })?;

       buffer.extend_from_slice(&chunk);

       // Update progress callback
       if let Some(cb) = &progress {
           cb(buffer.len() as u64, Some(content_length as u64));
       }
   }

   Ok(buffer)
   ```

5. **Error Mapping**:
   ```rust
   impl From<google_cloud_storage::Error> for CloudError {
       fn from(err: google_cloud_storage::Error) -> Self {
           match err {
               google_cloud_storage::Error::NotFound(_) => CloudError::ObjectNotFound(key.into()),
               google_cloud_storage::Error::Unauthorized(_) => CloudError::AuthenticationFailed(err.to_string()),
               google_cloud_storage::Error::Forbidden(_) => CloudError::PermissionDenied(err.to_string()),
               _ => CloudError::Other(err.to_string()),
           }
       }
   }
   ```

### Credential Resolution Order

Google Cloud credential chain (in order):
1. Explicit service account JSON from GcsConfig.credentials_json
2. Explicit service account file from GcsConfig.credentials_path
3. Explicit OAuth bearer token from GcsConfig.oauth_token (for testing)
4. Application Default Credentials (ADC):
   - Environment variable `GOOGLE_APPLICATION_CREDENTIALS` (path to service account JSON)
   - gcloud default credentials (`~/.config/gcloud/application_default_credentials.json`)
   - GCE/GKE metadata server (Workload Identity)
   - Cloud Run metadata server (service account)

### Retry Strategy

Configure GCS client with exponential backoff:
- Initial delay: 1 second
- Backoff multiplier: 2.0 (doubles each retry)
- Max delay: 32 seconds (GCS recommendation)
- Max retries: 3 (default, configurable via GcsConfig.max_retries)
- Retry on: Network errors, HTTP 429, HTTP 503, HTTP 502

### Resumable Upload Thresholds

- Minimum chunk size: 256KB (262,144 bytes) - GCS requirement
- Recommended chunk size: 1-8MB for better throughput
- Maximum chunk size: No strict limit, but 8MB is practical
- Maximum object size: 5TB - GCS limit
- Resumable upload session timeout: 7 days

### Security Considerations

- **Credentials in transit**: All GCS API calls use HTTPS (GCS requirement)
- **Credentials at rest**: Never log service account keys or tokens
- **Service accounts over keys**: Prefer Workload Identity (GKE, Cloud Run)
- **IAM permissions**: Document required IAM permissions:
  - `storage.objects.create` - Upload backups
  - `storage.objects.get` - Download backups
  - `storage.objects.delete` - Delete expired backups
  - `storage.objects.list` - List backups
  - `storage.buckets.get` - Check bucket access
- **Encryption at rest**: GCS default encryption (Google-managed or customer-managed keys)
- **Encryption in transit**: HTTPS enforced (GCS requirement)

### Performance Targets

- Upload throughput: >50 MB/s (depends on network)
- Download throughput: >100 MB/s (depends on network)
- Resumable upload overhead: <5% (vs simple upload)
- Small file upload (<5MB): <500ms
- List 1000 objects: <2 seconds
