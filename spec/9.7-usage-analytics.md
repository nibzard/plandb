# Phase 9.7: Usage Analytics Integration

## Overview

Usage Analytics Integration connects the monitoring system (Phase 14) with the query and plugin systems to provide AI-driven usage analytics and insights. This component analyzes query patterns, detects hot keys and cold data, identifies performance anomalies, and generates usage-based optimization recommendations.

### Core Objectives

1. **Query Pattern Analysis**: Cluster and analyze similar queries by structure and access patterns
2. **Hot Key Detection**: Identify frequently accessed keys and calculate access distribution skew
3. **Cold Data Detection**: Identify rarely accessed data for archive/cleanup recommendations
4. **Performance Anomaly Detection**: Detect latency spikes, error rate increases, and resource exhaustion
5. **Optimization Recommendations**: Generate actionable recommendations for indexing, caching, and partitioning
6. **Analytics Aggregation**: Aggregate metrics across time windows for trend analysis
7. **Event Integration**: Subscribe to monitoring events and emit recommendations as events

### Integration Points

- **Consumes**: Query execution events from monitoring (Phase 14)
- **Consumes**: Performance metrics from MetricsCollector
- **Consumes**: QueryPlan metadata from query planner (Phase 9.5)
- **Uses**: Entity/Topic cartridges for context
- **Produces**: UsageAnalytics events with recommendations
- **Enhances**: Query cache warming (Phase 9.6) with usage patterns

### Query Pattern Analysis

Query patterns are clustered by structural similarity to identify recurring access patterns:

**Pattern Fingerprinting**:

1. **Query Normalization**:
   - Remove literal values: `age > 25` → `age > ?`
   - Normalize whitespace and case
   - Extract query structure: `SELECT * FROM users WHERE ? > ?`
   - Generate fingerprint: SHA-256(structure)

2. **Pattern Clustering**:
   - Group queries by fingerprint
   - Track statistics per pattern:
     - Execution frequency (count)
     - Average execution time (EMA)
     - Rows scanned vs returned ratio
     - Cache hit rate
     - Time of day distribution

3. **Pattern Classification**:
   - **Point Lookup**: Single key equality (`id = ?`)
   - **Range Scan**: Inequality on indexed column (`age > ?`)
   - **Full Scan**: No predicates or non-indexed predicates
   - **Join Query**: Multiple table access
   - **Aggregation**: GROUP BY, COUNT, SUM
   - **Semantic Search**: Natural language query

**Pattern Statistics**:

```
struct QueryPattern {
    // Query fingerprint
    fingerprint: u64,  // SHA-256 hash of normalized structure

    // Query metadata
    query_type: QueryType,  // PointLookup, RangeScan, FullScan, etc.
    table_name: String,
    columns_accessed: Vec<String>,

    // Execution statistics
    execution_count: u64,
    first_seen: SystemTime,
    last_seen: SystemTime,
    avg_latency_ms: f64,  // Exponential moving average
    p50_latency_ms: f64,
    p95_latency_ms: f64,
    p99_latency_ms: f64,

    // Access patterns
    avg_rows_scanned: f64,
    avg_rows_returned: f64,
    scan_return_ratio: f64,  // High ratio = inefficient

    // Cache effectiveness
    cache_hit_rate: f64,
    plan_cache_hit_rate: f64,

    // Time distribution
    hourly_frequency: [u64; 24],  // Queries per hour
    day_of_week_frequency: [u64; 7],
}
```

**Pattern Analysis Algorithm**:

```rust
fn analyze_query_pattern(query: &QueryPlan, metrics: &ExecutionMetrics) -> PatternUpdate {
    // 1. Normalize and fingerprint
    let fingerprint = fingerprint_query(query);

    // 2. Extract metadata
    let query_type = classify_query(query);
    let columns = extract_columns(query);

    // 3. Get or create pattern
    let pattern = patterns.entry(fingerprint)
        .or_insert(QueryPattern::new(fingerprint, query_type, columns));

    // 4. Update statistics
    pattern.execution_count += 1;
    pattern.last_seen = SystemTime::now();
    pattern.avg_latency_ms = update_ema(pattern.avg_latency_ms, metrics.execution_time_ms);
    pattern.avg_rows_scanned = update_ema(pattern.avg_rows_scanned, metrics.rows_read);
    pattern.avg_rows_returned = update_ema(pattern.avg_rows_returned, metrics.rows_produced);

    // 5. Update percentiles (using t-digest for efficiency)
    pattern.update_percentiles(metrics.execution_time_ms);

    // 6. Update time distribution
    let hour = current_hour();
    pattern.hourly_frequency[hour] += 1;

    // 7. Calculate scan/return ratio
    pattern.scan_return_ratio = pattern.avg_rows_scanned / pattern.avg_rows_returned;

    PatternUpdate { fingerprint, pattern }
}
```

### Hot Key Detection

Hot keys are frequently accessed keys that may benefit from caching or indexing:

**Access Frequency Tracking**:

```
struct KeyAccessStats {
    // Key identifier
    key: Vec<u8>,  // Raw key bytes

    // Access statistics
    read_count: u64,
    write_count: u64,
    last_read: SystemTime,
    last_write: SystemTime,

    // Temporal patterns
    hourly_reads: [u64; 24],
    hourly_writes: [u64; 24],

    // Access distribution
    avg_read_latency_ms: f64,
    avg_write_latency_ms: f64,
}
```

**Hot Key Detection Algorithm**:

1. **Track Access Frequency**:
   - Increment read/write counters on each access
   - Update hourly access patterns
   - Calculate exponential moving average of latency

2. **Calculate Access Skew**:
   - Sort keys by access frequency (descending)
   - Calculate Zipf coefficient: Fit power law distribution
   - Calculate Gini coefficient: Measure inequality
   - High skew (>0.7) indicates hot spot pattern

3. **Identify Hot Keys**:
   - Top 1% of keys by access frequency
   - Keys with access rate > 100 ops/sec
   - Keys with latency > p95 + 2*stddev

4. **Hot Key Classification**:
   - **Read Hot**: High read frequency, low write frequency
   - **Write Hot**: High write frequency
   - **Hot Spot**: Very high frequency (>1000 ops/sec)
   - **Warm Spot**: Moderate frequency (10-100 ops/sec)

**Hot Key Report**:

```
struct HotKeyReport {
    // Hot key
    key: Vec<u8>,
    key_type: KeyType,  // PrimaryKey, SecondaryKey, ForeignKey

    // Access statistics
    read_frequency: f64,  // Reads per second
    write_frequency: f64,  // Writes per second
    total_frequency: f64,

    // Hotness score (0.0 to 1.0)
    hotness_score: f64,

    // Classification
    classification: HotKeyClassification,

    // Recommendation
    recommendation: HotKeyRecommendation,
}

enum HotKeyRecommendation {
    CacheInL1,  // Add to page cache
    CacheInL2,  // Add to node cache
    CreateIndex,  // Create secondary index
    Partition,  // Partition table by this key
    Replicate,  // Replicate to read replicas
}
```

### Cold Data Detection

Cold data is rarely accessed and may be a candidate for archiving:

**Cold Data Detection Algorithm**:

1. **Track Key Inactivity**:
   - Record last access timestamp per key
   - Calculate days since last access
   - Calculate access rate over last 30 days

2. **Identify Cold Keys**:
   - Keys not accessed in > 30 days
   - Keys with access rate < 0.1 ops/day
   - Keys with size > 1MB (large but cold)

3. **Cold Data Classification**:
   - **Archive Candidate**: Not accessed in > 90 days, size > 10MB
   - **Delete Candidate**: Not accessed in > 365 days, no foreign key references
   - **Compress Candidate**: Low access rate, large size

**Cold Data Report**:

```
struct ColdDataReport {
    // Cold key
    key: Vec<u8>,
    table_name: String,

    // Inactivity statistics
    days_since_last_access: u64,
    access_rate_last_30_days: f64,  // Accesses per day

    // Size information
    estimated_size_bytes: u64,
    size_on_disk_bytes: u64,

    // Classification
    classification: ColdDataClassification,

    // Recommendation
    recommendation: ColdDataRecommendation,
}

enum ColdDataRecommendation {
    ArchiveToS3,  // Move to cold storage
    ArchiveToGlacier,  // Move to long-term archival
    Compress,  // Compress in-place
    Delete,  // Safe to delete
    Keep,  // Keep (referenced by FK, etc.)
}
```

### Performance Anomaly Detection

Anomalies are deviations from normal performance patterns:

**Anomaly Types**:

1. **Latency Spike**: Sudden increase in query execution time
2. **Throughput Drop**: Sudden decrease in operations per second
3. **Error Rate Increase**: Sudden increase in error/panic rate
4. **Cache Miss Spike**: Sudden decrease in cache hit rate
5. **Connection Pool Exhaustion**: Inability to acquire connections
6. **Lock Contention**: Increase in transaction conflicts

**Anomaly Detection Algorithm**:

1. **Maintain Baseline**:
   - Calculate moving average of metrics (last 5 minutes)
   - Calculate standard deviation
   - Track percentiles (p50, p95, p99)

2. **Detect Anomalies**:
   - Latency spike: current > baseline + 3*stddev OR current > 3*baseline
   - Throughput drop: current < baseline - 3*stddev OR current < 0.5*baseline
   - Error rate: current_error_rate > 0.01 (1%)
   - Cache miss: hit_rate < 0.5 AND hit_rate < baseline - 2*stddev

3. **Correlate Anomalies**:
   - Find related events (commits, configuration changes)
   - Find related queries (same table, similar patterns)
   - Identify likely cause

**Anomaly Report**:

```
struct PerformanceAnomaly {
    // Anomaly metadata
    anomaly_id: u64,
    detected_at: SystemTime,
    anomaly_type: AnomalyType,

    // Deviation details
    metric_name: String,
    baseline_value: f64,
    current_value: f64,
    deviation_percent: f64,
    deviation_stddev: f64,

    // Severity
    severity: AnomalySeverity,

    // Correlation
    likely_cause: Option<String>,
    related_events: Vec<EventId>,
    affected_queries: Vec<QueryFingerprint>,
}

enum AnomalySeverity {
    Info,    // Minor deviation, no action needed
    Warning, // Moderate deviation, monitor
    Error,   // Significant deviation, investigate
    Critical, // Severe degradation, immediate action
}

### Optimization Recommendations

Recommendations are generated based on usage patterns and anomalies:

**Recommendation Types**:

1. **Index Creation**:
   - High-frequency point lookups without index
   - Range scans on non-indexed columns
   - Join columns without indexes

2. **Cache Warming**:
   - Pre-load hot keys into cache
   - Pre-execute frequent queries
   - Cache query results for predictable patterns

3. **Partitioning**:
   - Partition table by hot key for parallel access
   - Partition by time for time-series data
   - Partition by tenant for multi-tenant data

4. **Query Optimization**:
   - Rewrite inefficient queries (avoid SELECT *)
   - Add query hints for optimizer
   - Use prepared statements for repeated queries

5. **Schema Changes**:
   - Normalize denormalized data
   - Denormalize for read-heavy workloads
   - Change column types for better compression

**Recommendation Structure**:

```
struct Recommendation {
    // Recommendation metadata
    recommendation_id: u64,
    generated_at: SystemTime,
    recommendation_type: RecommendationType,

    // Description
    title: String,
    description: String,
    rationale: String,

    // Target

    target_name: String,

    // Implementation
    effort_level: EffortLevel,  // Trivial, Easy, Moderate, Complex
    sql_statement: Option<String>,
    config_change: Option<ConfigChange>,

    // Priority

    expires_at: Option<SystemTime>,  // Time-limited recommendations

    // Validation

}

    latency_reduction_percent: f64,
    throughput_increase_percent: f64,
    cost_reduction_percent: Option<f64>,
    storage_overhead_bytes: Option<u64>,
}

enum EffortLevel {
    Trivial,  // Config change, no downtime
    Easy,     // Index creation, short downtime
    Moderate, // Schema change, planned downtime
    Complex,  // Migration, extensive testing
}

    Low,      // Nice to have, minimal impact
    Medium,   // Worthwhile, moderate impact
    High,     // Significant impact, implement soon
    Critical, // Urgent, severe degradation

**Recommendation Generation Algorithm**:

```rust
fn generate_recommendations(patterns: &QueryPatternRegistry, hot_keys: &HotKeyRegistry) -> Vec<Recommendation> {
    let mut recommendations = Vec::new();

    // 1. Index recommendations
    for pattern in patterns.iter() {
        if pattern.execution_count < 100 {
            continue;  // Not enough data
        }

        if pattern.query_type == QueryType::FullScan {
            if pattern.avg_rows_scanned > 10000 && pattern.avg_rows_returned < 1000 {
                // Scanning lots but returning little
                recommendations.push(Recommendation {
                    recommendation_type: RecommendationType::CreateIndex,
                    title: format!("Create index on {}", pattern.table_name),
                    description: format!(
                        "Frequent full scans on {} ({} executions, {}ms avg latency). \
                         Adding an index could reduce latency by 80%.",
                        pattern.table_name, pattern.execution_count, pattern.avg_latency_ms
                    ),
                    target_type: RecommendationTarget::Table,
                    target_name: pattern.table_name.clone(),
                    estimated_benefit: ImpactEstimate {
                        latency_reduction_percent: 80.0,
                        throughput_increase_percent: 50.0,
                        cost_reduction_percent: None,
                        storage_overhead_bytes: Some(estimate_index_size(pattern)),
                    },
                    effort_level: EffortLevel::Easy,
                    sql_statement: Some(generate_index_sql(pattern)),
                    priority: if pattern.execution_count > 1000 {
                        RecommendationPriority::High
                    } else {
                        RecommendationPriority::Medium
                    },
                    confidence: 0.9,
                    ..Default::default()
                });
            }
        }
    }

    // 2. Cache warming recommendations
    for hot_key in hot_keys.top_k(100) {
        if hot_key.classification == HotKeyClassification::ReadHot {
            recommendations.push(Recommendation {
                recommendation_type: RecommendationType::CacheWarming,
                title: format!("Pre-load hot key into cache"),
                description: format!(
                    "Key {:?} is read hot ({} reads/sec). Pre-loading into L1 cache \
                     could reduce latency by 95%.",
                    hot_key.key, hot_key.read_frequency
                ),
                target_type: RecommendationTarget::Key,
                target_name: format!("{:?}", hot_key.key),
                estimated_benefit: ImpactEstimate {
                    latency_reduction_percent: 95.0,
                    throughput_increase_percent: 20.0,
                    cost_reduction_percent: None,
                    storage_overhead_bytes: Some(hot_key.key.len() as u64),
                },
                effort_level: EffortLevel::Trivial,
                priority: RecommendationPriority::Medium,
                confidence: 0.95,
                ..Default::default()
            });
        }
    }

    recommendations
}
```

## Integration with Monitoring Events

### Event Subscription

The usage analytics system subscribes to monitoring events:

```rust
struct UsageAnalyzer {
    metrics: Arc<MetricRegistry>,
    event_subscriber: EventSubscriber,

    // Analytics state
    patterns: Arc<RwLock<QueryPatternRegistry>>,
    hot_keys: Arc<RwLock<HotKeyRegistry>>,
    cold_data: Arc<RwLock<ColdDataRegistry>>,
    anomalies: Arc<RwLock<AnomalyRegistry>>,

    // Recommendation queue
    recommendations: Arc<Mutex<Vec<Recommendation>>>,

    // Aggregation state
    current_window: AggregationWindow,
    aggregations: BTreeMap<SystemTime, UsageAnalyticsSnapshot>,
}

impl UsageAnalyzer {
    pub async fn start(&mut self) -> Result<()> {
        // Subscribe to query execution events
        self.event_subscriber.subscribe(EventType::QueryExecution, {
            let analyzer = self.clone();
            move |event| {
                analyzer.handle_query_event(event);
            }
        }).await?;

        // Subscribe to performance sample events
        self.event_subscriber.subscribe(EventType::PerformanceSample, {
            let analyzer = self.clone();
            move |event| {
                analyzer.handle_performance_event(event);
            }
        }).await?;

        // Subscribe to commit events
        self.event_subscriber.subscribe(EventType::Commit, {
            let analyzer = self.clone();
            move |event| {
                analyzer.handle_commit_event(event);
            }
        }).await?;

        Ok(())
    }

    fn handle_query_event(&self, event: Event) {
        // Extract query execution metadata
        let query_id = event.get_query_id();
        let execution_time = event.get_execution_time();
        let rows_read = event.get_rows_read();
        let rows_returned = event.get_rows_returned();

        // Update pattern analysis
        let pattern_update = self.analyze_query_pattern(query_id, execution_time, rows_read, rows_returned);
        self.patterns.write().update(pattern_update);

        // Check for anomalies
        if let Some(anomaly) = self.detect_latency_anomaly(query_id, execution_time) {
            self.anomalies.write().add(anomaly);
            self.emit_anomaly_event(anomaly);
        }

        // Generate recommendations (debounced)
        if self.should_generate_recommendations() {
            let recommendations = self.generate_recommendations();
            self.recommendations.lock().extend(recommendations);
        }
    }

    fn emit_anomaly_event(&self, anomaly: PerformanceAnomaly) {
        let event = Event::new(EventType::PerformanceAnomaly)
            .with_payload(anomaly.to_payload())
            .with_severity(anomaly.severity.to_event_severity())
            .with_correlation_id(anomaly.anomaly_id);

        self.event_publisher.publish(event).await;
    }
}
```

### Event Emission

The usage analytics system emits recommendation events:

```rust
impl UsageAnalyzer {
    async fn emit_recommendation_event(&self, recommendation: &Recommendation) {
        let event = Event::new(EventType::OptimizationRecommendation)
            .with_payload(recommendation.to_payload())
            .with_priority(recommendation.priority.to_event_priority())
            .with_ttl(Duration::from_secs(86400))  // 24 hours
            .add_tag("recommendation_type", recommendation.recommendation_type.as_str())
            .add_tag("target", &recommendation.target_name)
            .add_tag("priority", recommendation.priority.as_str())
            .add_tag("confidence", &format!("{:.2}", recommendation.confidence));

        self.event_publisher.publish(event).await;
    }
}
```

## Performance Targets

### Analytics Overhead

1. **Query Execution Overhead**: < 5% increase in latency
   - Pattern update: < 100μs per query
   - Hot key tracking: < 50μs per query
   - Anomaly detection: < 200μs per query
   - Total overhead: < 350μs per query

2. **Memory Overhead**: < 100MB for analytics state
   - Pattern registry: ~50MB (10,000 patterns)
   - Hot key registry: ~20MB (100,000 keys)
   - Cold data registry: ~20MB (100,000 keys)
   - Anomaly registry: ~5MB (1,000 anomalies)
   - Aggregations: ~5MB

3. **CPU Overhead**: < 10% CPU usage
   - Background aggregation: ~2% CPU
   - Recommendation generation: ~3% CPU
   - Anomaly detection: ~2% CPU
   - Event handling: ~3% CPU

### Detection Accuracy

1. **Hot Key Detection**: > 95% precision, > 90% recall
   - Minimize false positives (non-hot keys flagged)
   - Minimize false negatives (missed hot keys)

2. **Anomaly Detection**: > 90% precision, > 85% recall
   - Minimize false alarms (normal fluctuations)
   - Detect real anomalies promptly

3. **Recommendation Quality**: > 80% confidence threshold
   - At least 80% of recommendations should be actionable
   - Estimated benefit within 20% of actual benefit
