# Phase 16.1: AWS SDK S3 Integration for NorthstarDB

## Purpose

Phase 16.1 implements production-ready AWS S3 integration using the official AWS SDK for Rust. This enables NorthstarDB to store backups, snapshots, and WAL archives in Amazon S3 with:

- **Automatic credential management**: IAM roles, environment variables, credential profiles
- **Streaming operations**: Efficient upload/download without buffering entire files
- **Multipart uploads**: Parallel uploads for large files (>5MB)
- **Retry logic**: Exponential backoff for transient failures
- **S3-compatible storage**: Support MinIO, LocalStack, Wasabi via custom endpoints

This phase replaces the placeholder S3Adapter from Phase 15.3 with a full implementation using aws-sdk-s3.

## Types

### S3Client

**Description**: AWS S3 client wrapper with NorthstarDB configuration

**Fields**:
- `client: aws_sdk_s3::Client` - AWS SDK S3 client
- `config: S3Config` - NorthstarDB S3 configuration
- `bucket: String` - Target bucket name
- `key_prefix: Option<String>` - Optional key prefix for namespacing

**Size**: 256 bytes + SDK client overhead

**Invariants**:
- `client` is configured with correct region and credentials
- `bucket` exists and is accessible
- All operations use configured retry strategy

### MultipartUploadState

**Description**: Tracks in-progress multipart upload

**Fields**:
- `upload_id: String` - S3 multipart upload session ID
- `key: String` - Object key being uploaded
- `parts: Vec<CompletedPart>` - List of successfully uploaded parts
- `part_number: u32` - Next part number to upload
- `total_bytes: u64` - Total upload size
- `uploaded_bytes: u64` - Bytes uploaded so far

**Size**: 128 bytes + vector allocations

**Invariants**:
- `part_number` is 1-indexed (S3 requirement)
- `parts` are stored in sequential order
- `uploaded_bytes` <= `total_bytes`

### UploadProgress

**Description**: Progress callback for upload operations

**Signature**: `fn(bytes_uploaded: u64, total_bytes: Option<u64>)`

**Purpose**: Allow caller to track upload progress for UI/monitoring

**Invariants**:
- `total_bytes` is None for streaming uploads (unknown size)
- Callback is invoked after each part/chunk

### DownloadProgress

**Description**: Progress callback for download operations

**Signature**: `fn(bytes_downloaded: u64, total_bytes: Option<u64>)`

**Purpose**: Allow caller to track download progress for UI/monitoring

**Invariants**:
- `total_bytes` is None if object size is unknown
- Callback is invoked after each chunk

## Functions

### S3Adapter::new(config: CloudStorageConfig) -> Result<Self>

**Purpose**: Create a new S3 adapter with AWS SDK client

**Parameters**:
- `config: CloudStorageConfig` - Cloud configuration with S3 settings

**Returns**: `Result<S3Adapter>` - Initialized adapter or error

**Algorithm**:
1. Extract S3Config from CloudStorageConfig
2. Validate S3Config (bucket name, region)
3. Create AWS SDK configuration loader:
   - Load region from S3Config
   - Set custom endpoint if configured (for MinIO/Wasabi)
   - Configure credential chain (env vars, profile, IAM role, explicit keys)
   - Set retry strategy (max 3 retries, exponential backoff)
   - Set timeout (default 30 seconds)
4. Build S3 client from configuration
5. Test connectivity by calling HeadBucket
6. Return S3Adapter on success

**Error Conditions**:
- `CloudError::InvalidRequest` - Missing or invalid configuration
- `CloudError::AuthenticationFailed` - Invalid credentials
- `CloudError::BucketNotFound` - Bucket does not exist or no access
- `CloudError::NetworkError` - Cannot reach S3 endpoint

**Concurrency**: Safe to share across threads (AWS SDK client is Arc + clone)

### S3Adapter::upload(&self, key: &str, data: &[u8], progress: Option<UploadProgress>) -> Result<String>

**Purpose**: Upload data to S3 (single-part or multipart)

**Parameters**:
- `key: &str` - Object key in bucket
- `data: &[u8]` - Data to upload
- `progress: Option<UploadProgress>` - Optional progress callback

**Returns**: `Result<String>` - Object ETag

**Algorithm**:
1. Apply key_prefix if configured
2. If data.len() > 5MB (5,242,880 bytes), use multipart upload:
   - Call upload_multipart() method
3. Else, use single-part upload:
   - Create PutObjectRequest with data as byte buffer
   - Set content length, content type (application/octet-stream)
   - Invoke S3 client put_object() operation
   - Await response
   - Extract ETag from response
4. Return ETag

**Error Conditions**:
- `CloudError::QuotaExceeded` - Bucket size limit reached
- `CloudError::PermissionDenied` - No write permission (s3:PutObject)
- `CloudError::NetworkError` - Upload failed after retries
- `CloudError::Timeout` - Upload exceeded timeout

**Concurrency**: Safe to call concurrently (multiple parallel uploads)

### S3Adapter::upload_multipart(&self, key: &str, data: &[u8], progress: Option<UploadProgress>) -> Result<String>

**Purpose**: Upload large objects using multipart upload API

**Parameters**:
- `key: &str` - Object key in bucket
- `data: &[u8]` - Data to upload (>5MB)
- `progress: Option<UploadProgress>` - Optional progress callback

**Returns**: `Result<String>` - Object ETag

**Algorithm**:
1. Apply key_prefix if configured
2. Calculate part size (default 16MB, configurable)
3. Split data into chunks of part_size
4. Create CreateMultipartUploadRequest
5. Invoke create_multipart_upload() to get upload_id
6. For each chunk:
   a. Spawn async task (respect max_concurrent_uploads limit)
   b. Create UploadPartRequest with upload_id and part_number
   c. Upload chunk as byte buffer
   d. Collect CompletedPart (part_number, e_tag)
   e. Update progress callback
   f. On error, abort multipart upload
7. Wait for all parts to complete
8. Create CompleteMultipartUploadRequest with parts list
9. Invoke complete_multipart_upload()
10. Return final ETag

**Error Conditions**:
- `CloudError::NetworkError` - One or more parts failed
- `CloudError::Timeout` - Upload exceeded timeout
- `CloudError::UploadCancelled` - Upload was aborted

**Concurrency**: Uploads parts in parallel using Semaphore to bound concurrency

### S3Adapter::download(&self, key: &str, progress: Option<DownloadProgress>) -> Result<Vec<u8>>

**Purpose**: Download object from S3

**Parameters**:
- `key: &str` - Object key in bucket
- `progress: Option<DownloadProgress>` - Optional progress callback

**Returns**: `Result<Vec<u8>>` - Downloaded data

**Algorithm**:
1. Apply key_prefix if configured
2. Create GetObjectRequest
3. Invoke get_object() operation
4. Stream response body to buffer:
   - Read chunks (default 8MB)
   - Accumulate into Vec<u8>
   - Update progress callback
5. Return buffer

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist (NoSuchKey)
- `CloudError::PermissionDenied` - No read permission (s3:GetObject)
- `CloudError::NetworkError` - Download failed after retries

**Concurrency**: Safe to call concurrently (multiple parallel downloads)

### S3Adapter::delete(&self, key: &str) -> Result<()>

**Purpose**: Delete object from S3

**Parameters**:
- `key: &str` - Object key to delete

**Returns**: `Result<()>` - Success or error

**Algorithm**:
1. Apply key_prefix if configured
2. Create DeleteObjectRequest
3. Invoke delete_object() operation
4. Return success

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist (may be OK)
- `CloudError::PermissionDenied` - No delete permission (s3:DeleteObject)

**Concurrency**: Safe to call concurrently

### S3Adapter::exists(&self, key: &str) -> Result<bool>

**Purpose**: Check if object exists in S3

**Parameters**:
- `key: &str` - Object key to check

**Returns**: `Result<bool>` - True if exists, false if not

**Algorithm**:
1. Apply key_prefix if configured
2. Create HeadObjectRequest
3. Invoke head_object() operation
4. Return true if success (200 OK)
5. Return false if NoSuchKey error
6. Return error for other failures

**Error Conditions**:
- `CloudError::PermissionDenied` - No read permission (s3:GetObject)

**Concurrency**: Safe to call concurrently

### S3Adapter::list(&self, prefix: &str) -> Result<Vec<String>>

**Purpose**: List objects with given prefix

**Parameters**:
- `prefix: &str` - Key prefix to filter (e.g., "backups/2026-01-")

**Returns**: `Result<Vec<String>>` - List of object keys

**Algorithm**:
1. Apply key_prefix if configured
2. Create ListObjectsV2Request with prefix
3. Invoke list_objects_v2() operation
4. Collect object keys from response.contents
5. While response.is_truncated:
   a. Set continuation_token from response.next_continuation_token
   b. Invoke list_objects_v2() again
   c. Accumulate more keys
6. Return sorted list

**Error Conditions**:
- `CloudError::PermissionDenied` - No list permission (s3:ListBucket)

**Concurrency**: Safe to call concurrently

### S3Adapter::get_object_size(&self, key: &str) -> Result<u64>

**Purpose**: Get object size without downloading

**Parameters**:
- `key: &str` - Object key

**Returns**: `Result<u64>` - Size in bytes

**Algorithm**:
1. Apply key_prefix if configured
2. Create HeadObjectRequest
3. Invoke head_object() operation
4. Extract content_length from response
5. Return size

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist

**Concurrency**: Safe to call concurrently

### resolve_credentials(config: &S3Config) -> Result<Credentials>

**Purpose**: Load AWS credentials from multiple sources

**Parameters**:
- `config: &S3Config` - S3 configuration

**Returns**: `Result<Credentials>` - AWS credentials

**Algorithm**:
1. If explicit access_key_id and secret_access_key provided:
   - Return Credentials::from_keys()
2. Else, use AWS credential chain:
   - Check environment variables (AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY)
   - Check AWS credential file (~/.aws/credentials)
   - Check IAM role credentials (EC2, ECS, Lambda)
   - Check for web identity token (EKS pods)
3. Return first valid credentials

**Error Conditions**:
- `CloudError::AuthenticationFailed` - No valid credentials found

**Concurrency**: Safe to call

### build_retry_strategy(max_retries: u32) -> RetryConfig

**Purpose**: Configure AWS SDK retry behavior

**Parameters**:
- `max_retries: u32` - Maximum retry attempts

**Returns**: `RetryConfig` - AWS SDK retry configuration

**Algorithm**:
1. Create RetryConfig with max_attempts = max_retries + 1
2. Set backoff strategy to exponential:
   - Initial delay: 1 second
   - Multiplier: 2.0
   - Max delay: 20 seconds
3. Configure retryable errors:
   - Network errors
   - HTTP 5xx errors
   - HTTP 429 (Too Many Requests)
   - Throttling exceptions
4. Return config

**Error Conditions**: None

**Concurrency**: Safe to call

## Invariants

- **Multipart parts are sequential**: Part numbers must be 1, 2, 3, ... (no gaps)
- **Uploads complete atomically**: Multipart uploads only visible after complete_multipart_upload()
- **ETags are returned**: All uploads return ETag for integrity verification
- **Key prefix is applied**: All operations prepend configured key_prefix
- **Credentials are never logged**: Access keys and secrets excluded from logs/errors
- **Retries are exponential**: Failed requests retry with exponential backoff (1s, 2s, 4s, 8s, ...)
- **Concurrent uploads are bounded**: Semaphore enforces max_concurrent_uploads limit
- **Streaming is used**: Large files streamed in chunks, not buffered entirely in memory

### Key Implementation Details

1. **AWS SDK Client Creation**:
   ```rust
   use aws_config::Region;
   use aws_sdk_s3::Client;
   use aws_credential_types::Credentials;

   // Load credentials from config or environment
   let credentials = if !s3_config.access_key_id.is_empty() {
       Credentials::from_keys(
           s3_config.access_key_id.clone(),
           s3_config.secret_access_key.clone(),
           s3_config.session_token.clone(),
       )
   } else {
       // Use default credential chain (env, profile, IAM)
       Credentials::load_defaults().await?
   };

   // Build SDK config
   let sdk_config = aws_config::AwsConfig::builder()
       .region(Region::new(s3_config.region.clone()))
       .credentials_provider(credentials)
       .endpoint_url(s3_config.endpoint.clone()) // For MinIO/Wasabi
       .build()
       .await;

   let s3_client = Client::new(&sdk_config);
   ```

2. **Single-Part Upload**:
   ```rust
   use aws_sdk_s3::types::ByteStream;

   let byte_stream = ByteStream::from(data.to_vec());
   let put_request = s3_client.put_object()
       .bucket(&self.bucket)
       .key(full_key)
       .content_length(data.len() as i64)
       .body(byte_stream);

   let response = put_request.send().await?;
   Ok(response.e_tag.unwrap_or_default())
   ```

3. **Multipart Upload**:
   ```rust
   use aws_sdk_s3::types::CompletedPart;
   use tokio::sync::Semaphore;

   // Initiate multipart upload
   let create_response = s3_client.create_multipart_upload()
       .bucket(&self.bucket)
       .key(full_key)
       .send()
       .await?;
   let upload_id = create_response.upload_id.unwrap();

   // Split into parts and upload in parallel
   let semaphore = Arc::new(Semaphore::new(config.max_concurrent_uploads));
   let mut tasks = Vec::new();

   for (i, chunk) in data.chunks(part_size).enumerate() {
       let permit = semaphore.clone().acquire_owned().await?;
       let client = s3_client.clone();
       let upload_id = upload_id.clone();
       let bucket = self.bucket.clone();
       let key = full_key.clone();

       let task = tokio::spawn(async move {
           let _permit = permit; // Hold permit for duration of upload
           let part_number = (i + 1) as i32;

           let upload_result = client.upload_part()
               .bucket(&bucket)
               .key(&key)
               .upload_id(&upload_id)
               .part_number(part_number)
               .body(ByteStream::from(chunk.to_vec()))
               .send()
               .await?;

           Ok(CompletedPart::builder()
               .part_number(part_number)
               .e_tag(upload_result.e_tag.unwrap_or_default())
               .build())
       });

       tasks.push(task);
   }

   // Wait for all parts and collect ETags
   let parts: Vec<CompletedPart> = futures::future::try_join_all(tasks)
       .await?
       .into_iter()
       .collect::<Result<Vec<_>, _>>()?;

   // Complete multipart upload
   let complete_response = s3_client.complete_multipart_upload()
       .bucket(&self.bucket)
       .key(full_key)
       .upload_id(&upload_id)
       .multipart_upload(
           CompletedMultipartUpload::builder()
               .set_parts(Some(parts))
               .build()
       )
       .send()
       .await?;

   Ok(complete_response.e_tag.unwrap_or_default())
   ```

4. **Streaming Download**:
   ```rust
   let get_response = s3_client.get_object()
       .bucket(&self.bucket)
       .key(full_key)
       .send()
       .await?;

   let mut buffer = Vec::new();
   let mut stream = get_response.body;

   while let Some(chunk) = stream.next().await {
       let chunk = chunk?;
       buffer.extend_from_slice(&chunk);
       // Update progress callback
   }

   Ok(buffer)
   ```

5. **Error Mapping**:
   ```rust
   impl From<aws_sdk_s3::Error> for CloudError {
       fn from(err: aws_sdk_s3::Error) -> Self {
           match err {
               aws_sdk_s3::Error::NoSuchKey(_) => CloudError::ObjectNotFound(key.into()),
               aws_sdk_s3::Error::Unauthorized(_) => CloudError::AuthenticationFailed(err.to_string()),
               aws_sdk_s3::Error::AccessDenied(_) => CloudError::PermissionDenied(err.to_string()),
               _ => CloudError::Other(err.to_string()),
           }
       }
   }
   ```

### Credential Resolution Order

AWS SDK credential chain (in order):
1. Explicit access keys from S3Config (if provided)
2. Environment variables: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`
3. AWS credential file: `~/.aws/credentials` (profile from `AWS_PROFILE`)
4. IAM role credentials (EC2 instance profile, ECS task role, Lambda execution role)
5. Web identity token (EKS pod with IRSA)

### Retry Strategy

Configure AWS SDK with exponential backoff:
- Initial delay: 1 second
- Backoff multiplier: 2.0 (doubles each retry)
- Max delay: 20 seconds
- Max retries: 3 (default, configurable via S3Config.max_retries)
- Retry on: Network errors, HTTP 5xx, HTTP 429 (throttling)

### Multipart Upload Thresholds

- Minimum part size: 5MB (5,242,880 bytes) - S3 requirement
- Default part size: 16MB (16,777,216 bytes) - Good balance
- Maximum part size: 5GB (5,368,709,120 bytes) - S3 limit
- Maximum number of parts: 10,000 - S3 limit
- Maximum object size: 5TB - S3 limit

### Integration with CloudStorageAdapter Trait

The S3Adapter implements all trait methods:
- `config()` - Returns reference to CloudStorageConfig
- All async methods return `Pin<Box<Future<Output = Result<...>>>>`

### Security Considerations

- **Credentials in transit**: All S3 API calls use HTTPS (AWS SDK default)
- **Credentials at rest**: Never log access keys or secret keys
- **IAM roles over keys**: Prefer IAM role credentials (EC2, ECS, Lambda)
- **Bucket policies**: Document required IAM permissions:
  - `s3:PutObject` - Upload backups
  - `s3:GetObject` - Download backups
  - `s3:DeleteObject` - Delete expired backups
  - `s3:ListBucket` - List backups
- **Encryption at rest**: Enable S3 default encryption (AES-256 or KMS)
- **Encryption in transit**: HTTPS enforced (S3 requirement)

### Performance Targets

- Upload throughput: >50 MB/s (depends on network)
- Download throughput: >100 MB/s (depends on network)
- Multipart upload overhead: <5% (vs single-part)
- Small file upload (<5MB): <500ms
- List 1000 objects: <2 seconds
