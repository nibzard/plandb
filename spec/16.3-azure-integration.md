# Phase 16.3: Azure Blob Storage Integration for NorthstarDB

## Purpose

Phase 16.3 implements production-ready Azure Blob Storage integration using the official Azure SDK for Rust. This enables NorthstarDB to store backups, snapshots, and WAL archives in Azure Blob Storage with:

- **Automatic credential management**: Connection strings, access keys, SAS tokens, Azure AD (Managed Identity)
- **Streaming operations**: Efficient upload/download without buffering entire files
- **Block blob uploads**: Large file uploads with automatic retry and parallel block upload
- **Retry logic**: Exponential backoff for transient failures
- **Compatibility**: Support for Azurite emulator (local development and testing)

This phase replaces the placeholder AzureAdapter from Phase 15.3 with a full implementation using azure_storage and azure_storage_blobs crates.

## Types

### AzureClient

**Description**: Azure Blob Storage client wrapper with NorthstarDB configuration

**Fields**:
- `client: azure_storage_blobs::blob::BlobClient` - Azure blob client
- `container_client: azure_storage_blobs::container::ContainerClient` - Container client
- `config: AzureConfig` - NorthstarDB Azure configuration
- `container: String` - Target container name
- `key_prefix: Option<String>` - Optional key prefix for namespacing

**Size**: 256 bytes + client overhead

**Invariants**:
- `client` is configured with correct credentials
- `container` exists and is accessible
- All operations use configured retry strategy

### BlockUploadState

**Description**: Tracks in-progress block blob upload

**Fields**:
- `block_ids: Vec<String>` - List of block IDs uploaded
- `total_bytes: u64` - Total upload size
- `uploaded_bytes: u64` - Bytes uploaded so far
- `block_size: usize` - Upload block size (default: 4MB)

**Size**: 128 bytes + vector allocations

**Invariants**:
- `block_ids` are base64-encoded block IDs
- `uploaded_bytes` <= `total_bytes`
- `block_size` is aligned to 4MB (Azure requirement)

### UploadProgress

**Description**: Progress callback for upload operations

**Signature**: `fn(bytes_uploaded: u64, total_bytes: Option<u64>)`

**Purpose**: Allow caller to track upload progress for UI/monitoring

**Invariants**:
- `total_bytes` is None for streaming uploads (unknown size)
- Callback is invoked after each block/chunk

### DownloadProgress

**Description**: Progress callback for download operations

**Signature**: `fn(bytes_downloaded: u64, total_bytes: Option<u64>)`

**Purpose**: Allow caller to track download progress for UI/monitoring

**Invariants**:
- `total_bytes` is None if blob size is unknown
- Callback is invoked after each chunk

## Functions

### AzureAdapter::new(config: CloudStorageConfig) -> Result<Self>

**Purpose**: Create a new Azure adapter with Azure SDK client

**Parameters**:
- `config: CloudStorageConfig` - Cloud configuration with Azure settings

**Returns**: `Result<AzureAdapter>` - Initialized adapter or error

**Algorithm**:
1. Extract AzureConfig from CloudStorageConfig
2. Validate AzureConfig (storage account, container)
3. Determine credential source:
   a. If explicit connection_string provided, parse and use
   b. If explicit access_key provided, create shared key credentials
   c. If explicit sas_token provided, use SAS token
   d. Otherwise, use DefaultAzureCredential (Managed Identity, env vars, CLI)
4. Create Azure Storage configuration:
   - Set storage account from AzureConfig
   - Set credentials (connection string, access key, SAS, or Azure AD)
   - Configure timeout (default 30 seconds)
   - Set retry strategy (max 3 retries, exponential backoff)
5. Build blob client and container client
6. Test connectivity by checking container existence
7. Return AzureAdapter on success

**Error Conditions**:
- `CloudError::InvalidRequest` - Missing or invalid configuration
- `CloudError::AuthenticationFailed` - Invalid credentials
- `CloudError::BucketNotFound` - Container does not exist or no access
- `CloudError::NetworkError` - Cannot reach Azure endpoint

**Concurrency**: Safe to share across threads (Azure clients are Arc + clone)

### AzureAdapter::upload(&self, key: &str, data: &[u8], progress: Option<UploadProgress>) -> Result<String>

**Purpose**: Upload data to Azure Blob Storage (simple or block upload)

**Parameters**:
- `key: &str` - Blob key in container
- `data: &[u8]` - Data to upload
- `progress: Option<UploadProgress>` - Optional progress callback

**Returns**: `Result<String>` - Blob ETag

**Algorithm**:
1. Apply key_prefix if configured
2. If data.len() > 256MB (268,435,456 bytes), use block blob upload:
   - Call upload_block_blob() method
3. Else, use simple put blob:
   - Create PutBlobRequest with data as byte buffer
   - Set content type (application/octet-stream)
   - Invoke blob client put_blob() operation
   - Await response
   - Extract ETag from response
4. Return ETag

**Error Conditions**:
- `CloudError::QuotaExceeded` - Container size limit reached
- `CloudError::PermissionDenied` - No write permission
- `CloudError::NetworkError` - Upload failed after retries
- `CloudError::Timeout` - Upload exceeded timeout

**Concurrency**: Safe to call concurrently (multiple parallel uploads)

### AzureAdapter::upload_block_blob(&self, key: &str, data: &[u8], progress: Option<UploadProgress>) -> Result<String>

**Purpose**: Upload large objects using block blob upload API

**Parameters**:
- `key: &str` - Blob key in container
- `data: &[u8]` - Data to upload (>256MB)
- `progress: Option<UploadProgress>` - Optional progress callback

**Returns**: `Result<String>` - Blob ETag

**Algorithm**:
1. Apply key_prefix if configured
2. Calculate block size (4MB or larger, must be multiple of 4MB)
3. Split data into chunks of block_size
4. For each chunk:
   a. Generate unique block ID (base64-encoded GUID)
   b. Spawn async task (respect max_concurrent_uploads limit)
   c. Upload chunk as block using put_block()
   d. Collect block ID
   e. Update progress callback
5. Wait for all blocks to complete
6. Create commit block list request with block IDs
7. Invoke put_block_list() to commit the blob
8. Return final ETag

**Error Conditions**:
- `CloudError::NetworkError` - One or more blocks failed
- `CloudError::Timeout` - Upload exceeded timeout
- `CloudError::UploadCancelled` - Upload was aborted

**Concurrency**: Uploads blocks in parallel using Semaphore to bound concurrency

### AzureAdapter::download(&self, key: &str, progress: Option<DownloadProgress>) -> Result<Vec<u8>>

**Purpose**: Download blob from Azure Blob Storage

**Parameters**:
- `key: &str` - Blob key in container
- `progress: Option<DownloadProgress>` - Optional progress callback

**Returns**: `Result<Vec<u8>>` - Downloaded data

**Algorithm**:
1. Apply key_prefix if configured
2. Create get_blob() request
3. Invoke download() operation
4. Stream response body to buffer:
   - Read chunks (default 8MB)
   - Accumulate into Vec<u8>
   - Update progress callback
5. Return buffer

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist (404)
- `CloudError::PermissionDenied` - No read permission
- `CloudError::NetworkError` - Download failed after retries

**Concurrency**: Safe to call concurrently (multiple parallel downloads)

### AzureAdapter::delete(&self, key: &str) -> Result<()>

**Purpose**: Delete blob from Azure Blob Storage

**Parameters**:
- `key: &str` - Blob key to delete

**Returns**: `Result<()>` - Success or error

**Algorithm**:
1. Apply key_prefix if configured
2. Create delete_blob() request
3. Invoke delete() operation
4. Return success

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist (may be OK)
- `CloudError::PermissionDenied` - No delete permission

**Concurrency**: Safe to call concurrently

### AzureAdapter::exists(&self, key: &str) -> Result<bool>

**Purpose**: Check if blob exists in Azure Blob Storage

**Parameters**:
- `key: &str` - Blob key to check

**Returns**: `Result<bool>` - True if exists, false if not

**Algorithm**:
1. Apply key_prefix if configured
2. Create get_blob_properties() request
3. Invoke get_properties() operation
4. Return true if success (200 OK)
5. Return false if NotFound error (404)
6. Return error for other failures

**Error Conditions**:
- `CloudError::PermissionDenied` - No read permission

**Concurrency**: Safe to call concurrently

### AzureAdapter::list(&self, prefix: &str) -> Result<Vec<String>>

**Purpose**: List blobs with given prefix

**Parameters**:
- `prefix: &str` - Key prefix to filter (e.g., "backups/2026-01-")

**Returns**: `Result<Vec<String>>` - List of blob keys

**Algorithm**:
1. Apply key_prefix if configured
2. Create list_blobs() request with prefix
3. Invoke list() operation
4. Collect blob keys from response.blobs
5. While response.next_marker is present:
   a. Set marker from response.next_marker
   b. Invoke list() again
   c. Accumulate more keys
6. Return sorted list

**Error Conditions**:
- `CloudError::PermissionDenied` - No list permission

**Concurrency**: Safe to call concurrently

### AzureAdapter::get_object_size(&self, key: &str) -> Result<u64>

**Purpose**: Get blob size without downloading

**Parameters**:
- `key: &str` - Blob key

**Returns**: `Result<u64>` - Size in bytes

**Algorithm**:
1. Apply key_prefix if configured
2. Create get_blob_properties() request
3. Invoke get_properties() operation
4. Extract content_length from response
5. Return size

**Error Conditions**:
- `CloudError::ObjectNotFound` - Key does not exist

**Concurrency**: Safe to call concurrently

### resolve_credentials(config: &AzureConfig) -> Result<StorageCredentials>

**Purpose**: Load Azure credentials from multiple sources

**Parameters**:
- `config: &AzureConfig` - Azure configuration

**Returns**: `Result<StorageCredentials>` - Azure credentials

**Algorithm**:
1. If explicit connection_string provided:
   - Parse connection string
   - Create StorageCredentials::from_connection_string()
   - Return credentials
2. If explicit access_key provided:
   - Create shared key credentials
   - Return credentials
3. If explicit sas_token provided:
   - Create SAS token credentials
   - Return credentials
4. Otherwise, use DefaultAzureCredential:
   - Check environment variables (AZURE_STORAGE_ACCOUNT, AZURE_STORAGE_KEY)
   - Check managed identity (Azure VM, App Service, AKS)
   - Check Azure CLI credentials
   - Return first valid credentials
5. If no valid credentials, return error

**Error Conditions**:
- `CloudError::AuthenticationFailed` - No valid credentials found
- `CloudError::InvalidRequest` - Connection string is malformed

**Concurrency**: Safe to call

### build_retry_strategy(max_retries: u32) -> RetryOptions

**Purpose**: Configure Azure SDK retry behavior

**Parameters**:
- `max_retries: u32` - Maximum retry attempts

**Returns**: `RetryOptions` - Azure retry configuration

**Algorithm**:
1. Create RetryOptions with max_attempts = max_retries + 1
2. Set backoff strategy to exponential:
   - Initial delay: 1 second
   - Multiplier: 2.0
   - Max delay: 60 seconds
3. Configure retryable errors:
   - Network errors (connection reset, timeout)
   - HTTP 429 (Too Many Requests)
   - HTTP 503 (Service Unavailable)
   - HTTP 500 (Internal Server Error)
4. Return config

**Error Conditions**: None

**Concurrency**: Safe to call

## Invariants

- **Block uploads are parallel**: Blocks uploaded concurrently for performance
- **Uploads complete atomically**: Block blobs only visible after put_block_list()
- **ETags are returned**: All uploads return ETag for integrity verification
- **Key prefix is applied**: All operations prepend configured key_prefix
- **Credentials are never logged**: Access keys and SAS tokens excluded from logs/errors
- **Retries are exponential**: Failed requests retry with exponential backoff (1s, 2s, 4s, 8s, ...)
- **Concurrent uploads are bounded**: Semaphore enforces max_concurrent_uploads limit
- **Streaming is used**: Large files streamed in blocks, not buffered entirely in memory

### Key Implementation Details

1. **Azure Client Creation**:
   ```rust
   use azure_storage::StorageCredentials;
   use azure_storage_blobs::{BlobClient, ContainerClient};
   use azure_identity::DefaultAzureCredential;

   // Load credentials from config or Azure AD
   let credentials = if let Some(conn_str) = &azure_config.connection_string {
       // Connection string
       StorageCredentials::from_connection_string(conn_str)?
   } else if !azure_config.access_key.is_empty() {
       // Shared key (access key)
       StorageCredentials::access_key(
           &azure_config.storage_account,
           &azure_config.access_key
       )
   } else if let Some(sas_token) = &azure_config.sas_token {
       // SAS token
       StorageCredentials::sas_token(sas_token.clone())
   } else {
       // DefaultAzureCredential (Managed Identity, env vars, Azure CLI)
       let default_credential = DefaultAzureCredential::default();
       StorageCredentials::token_credential(
           &azure_config.storage_account,
           default_credential
       )
   };

   // Build blob client
   let blob_client = BlobClient::new(
       &format!("{}.blob.core.windows.net", azure_config.storage_account),
       &azure_config.container,
       credentials.clone(),
   );

   let container_client = ContainerClient::new(
       &format!("{}.blob.core.windows.net", azure_config.storage_account),
       &azure_config.container,
       credentials,
   );
   ```

2. **Simple Upload (Put Blob)**:
   ```rust
   use azure_storage_blobs::prelude::*;
   use bytes::Bytes;

   let blob_client = self.blob_client.clone();
   let blob_client = blob_client.blob_name(full_key);

   let byte_stream = Bytes::from(data.to_vec());
   let put_response = blob_client
       .put_blob()
       .content_type("application/octet-stream")
       .body(byte_stream)
       .execute()
       .await?;

   Ok(put_response.e_tag.unwrap_or_default())
   ```

3. **Block Blob Upload**:
   ```rust
   use azure_storage_blobs::prelude::*;
   use tokio::sync::Semaphore;
   use uuid::Uuid;

   const BLOCK_SIZE: usize = 4 * 1024 * 1024; // 4MB (Azure requirement)

   let blob_client = self.blob_client.clone();
   let blob_client = blob_client.blob_name(full_key);

   // Upload blocks in parallel
   let semaphore = Arc::new(Semaphore::new(config.max_concurrent_uploads));
   let mut tasks = Vec::new();
   let mut block_ids = Vec::new();

   for (i, chunk) in data.chunks(BLOCK_SIZE).enumerate() {
       let permit = semaphore.clone().acquire_owned().await?;
       let client = blob_client.clone();
       let block_id = base64::encode(format!("{:010x}", i));

       let task = tokio::spawn(async move {
           let _permit = permit;

           client
               .put_block()
               .block_id(&block_id)
               .body(chunk.to_vec())
               .execute()
               .await?;

           Ok::<_, CloudError>(block_id)
       });

       tasks.push(task);
   }

   // Wait for all blocks
   let block_ids: Vec<String> = futures::future::try_join_all(tasks)
       .await?
       .into_iter()
       .collect::<Result<Vec<_>, _>>()?;

   // Commit block list
   let commit_response = blob_client
       .put_block_list()
       .block_list(block_ids.clone())
       .execute()
       .await?;

   Ok(commit_response.e_tag.unwrap_or_default())
   ```

4. **Streaming Download**:
   ```rust
   use azure_storage_blobs::prelude::*;

   let blob_client = self.blob_client.clone();
   let blob_client = blob_client.blob_name(full_key);

   let download_response = blob_client
       .download()
       .execute()
       .await?;

   let content_length = download_response.blob.content_length as usize;
   let mut buffer = Vec::with_capacity(content_length);
   let mut stream = download_response.blob.data;

   while let Some(chunk_result) = stream.next().await {
       let chunk = chunk_result.map_err(|e| {
           CloudError::NetworkError(format!("Download stream error: {}", e))
       })?;

       buffer.extend_from_slice(&chunk);

       // Update progress callback
       if let Some(cb) = &progress {
           cb(buffer.len() as u64, Some(content_length as u64));
       }
   }

   Ok(buffer)
   ```

5. **Error Mapping**:
   ```rust
   impl From<azure_storage::Error> for CloudError {
       fn from(err: azure_storage::Error) -> Self {
           match err {
               azure_storage::Error::HTTP(http_err) => {
                   match http_err.status() {
                       Some(reqwest::StatusCode::NOT_FOUND) => {
                           CloudError::ObjectNotFound(key.into())
                       }
                       Some(reqwest::StatusCode::UNAUTHORIZED) => {
                           CloudError::AuthenticationFailed(err.to_string())
                       }
                       Some(reqwest::StatusCode::FORBIDDEN) => {
                           CloudError::PermissionDenied(err.to_string())
                       }
                       _ => CloudError::Other(err.to_string()),
                   }
               }
               _ => CloudError::Other(err.to_string()),
           }
       }
   }
   ```

### Credential Resolution Order

Azure credential chain (in order):
1. Explicit connection string from AzureConfig.connection_string
2. Explicit access key from AzureConfig.access_key (shared key)
3. Explicit SAS token from AzureConfig.sas_token
4. DefaultAzureCredential:
   - Environment variables (AZURE_STORAGE_ACCOUNT, AZURE_STORAGE_KEY)
   - Managed identity (Azure VM, App Service, AKS pod identity)
   - Azure CLI credentials (az login)
   - Visual Studio Code credentials

### Retry Strategy

Configure Azure SDK with exponential backoff:
- Initial delay: 1 second
- Backoff multiplier: 2.0 (doubles each retry)
- Max delay: 60 seconds (Azure recommendation)
- Max retries: 3 (default, configurable via AzureConfig.max_retries)
- Retry on: Network errors, HTTP 429, HTTP 503, HTTP 500

### Block Blob Upload Thresholds

- Minimum block size: 4MB (4,194,304 bytes) - Azure recommendation
- Recommended block size: 4-8MB for better throughput
- Maximum block size: 100MB (104,857,600 bytes) - Azure limit
- Maximum number of blocks: 50,000 - Azure limit
- Maximum blob size: 4.75TB - Azure limit (block blob)
- Simple upload limit: 256MB - Use block blob upload for larger files

### Security Considerations

- **Credentials in transit**: All Azure API calls use HTTPS (Azure requirement)
- **Credentials at rest**: Never log access keys or SAS tokens
- **Managed identity over keys**: Prefer Managed Identity (Azure VM, AKS, App Service)
- **Azure RBAC**: Document required IAM permissions:
  - `Microsoft.Storage/storageAccounts/blobServices/containers/read` - List containers
  - `Microsoft.Storage/storageAccounts/blobServices/containers/blobs/read` - Download blobs
  - `Microsoft.Storage/storageAccounts/blobServices/containers/blobs/write` - Upload blobs
  - `Microsoft.Storage/storageAccounts/blobServices/containers/blobs/delete` - Delete blobs
- **Encryption at rest**: Azure Blob Storage default encryption (Microsoft-managed keys)
- **Encryption in transit**: HTTPS enforced (Azure requirement)

### Performance Targets

- Upload throughput: >50 MB/s (depends on network)
- Download throughput: >100 MB/s (depends on network)
- Block blob upload overhead: <5% (vs simple upload)
- Small file upload (<256MB): <500ms
- List 1000 blobs: <2 seconds
