# Phase 9.4: Entity Extraction Plugin

## Overview

The Entity Extraction Plugin provides intelligent analysis of database commits, automatically extracting and structuring entities, topics, and relationships from mutations using LLM function calling. This transforms raw commit data into a searchable knowledge graph.

### Core Objectives

1. **Automatic Entity Detection**: Extract entities (files, functions, people, topics, configs) from mutations
2. **Topic Categorization**: Organize entities into semantic topics and categories
3. **Relationship Discovery**: Identify relationships between entities
4. **Confidence Scoring**: Assign confidence scores to extracted data
5. **Time-Travel Support**: Link all extractions to source commits for historical analysis

### Integration Points

- **Consumes**: CommitEvent stream from Phase 8
- **Uses**: LlmProvider from Phase 9.1 for function calling
- **Implements**: Plugin trait from Phase 9.2
- **Produces**: Entity, Topic, Relationship cartridges

## Natural Language Description

### Entity Extraction

The plugin monitors the commit stream and analyzes each mutation to extract meaningful entities:

```
When a developer commits changes to src/db.zig:
- Extract File entity with path="src/db.zig", language="zig"
- Extract Function entities for modified/added functions
- Detect Topic associations (e.g., "database core", "btree implementation")
- Find Relationships (File contains Functions, Functions use Topics)
```

### Topic Discovery

Topics emerge naturally from entity analysis:

```
From mutations across multiple files:
- Detect pattern: src/pager.zig, src/btree.zig, src/db.zig
- Infer Topic: "storage layer" with entities {pager, btree, db}
- Categorize: "infrastructure" > "storage"
- Extract Keywords: [pager, btree, page, allocation, io]
```

### Relationship Detection

Entities form relationships through co-occurrence and semantic analysis:

```
Relationship types:
- CONTAINS: File contains Function
- USES: Function uses Topic
- MODIFIES: Person modifies File
- RELATED_TO: Entity related_to Entity (semantic)
- IMPLEMENTS: Function implements Topic
```

## Topic Extraction and Categorization

### Topic Hierarchy

```
Root Categories:
├── feature        (new functionality)
├── bugfix         (issue resolution)
├── refactor       (code restructuring)
├── infrastructure (build, ci, deployment)
├── documentation  (docs, comments)
├── performance    (optimizations)
└── testing        (tests, benchmarks)

Sub-categories:
feature/auth
feature/storage
bugfix/crash
refactor/api
infrastructure/ci
```

### Topic Detection Algorithm

1. **Keyword Analysis**: Match mutations against topic keyword lists
2. **File Path Analysis**: Infer topics from file locations (e.g., `src/auth/*` → `feature/auth`)
3. **Commit Message Analysis**: Extract topics from natural language commit messages
4. **Semantic Clustering**: Group related mutations into topics using embeddings

## Relationship Detection

### Relationship Types

```rust
enum RelationshipType {
    Contains,      // File contains Function
    Uses,          // Function uses Topic
    Modifies,      // Person modifies File
    RelatedTo,     // Semantic relationship
    Implements,    // Function implements Topic
    Calls,         // Function calls Function

```

### Relationship Discovery

1. **Structural Analysis**: Parse code to find CONTAINS, CALLS relationships
2. **Co-occurrence**: Entities appearing together suggest RELATES_TO
3. **Semantic Analysis**: LLM detects IMPLEMENTS, USES relationships
4. **Temporal Patterns**: Frequent co-modification suggests coupling

## Entity Cartridge Storage Format

### In-Memory Structure

```rust
struct EntityCartridge {
    entities: HashMap<String, Entity>,  // id → Entity
    by_type: HashMap<EntityType, Vec<String>>,  // type → [ids]
    by_name: HashMap<String, String>,   // name → id
    by_commit: HashMap<u64, Vec<String>>,  // commit_id → [ids]
}

struct TopicCartridge {
    topics: HashMap<String, Topic>,
    by_category: HashMap<String, Vec<String>>,  // category → [topic_ids]
    by_keyword: HashMap<String, Vec<String>>,    // keyword → [topic_ids]
}

struct RelationshipCartridge {
    relationships: HashMap<String, Relationship>,
    from_index: HashMap<String, Vec<String>>,  // entity_id → [rel_ids]
    to_index: HashMap<String, Vec<String>>,    // entity_id → [rel_ids]
}
```

### Persistence Format

Entities are persisted to B+tree with key structure:

```
Entity Keys:
- "entity:<id>" → Entity data
- "entity:type:<type>" → [entity_ids]
- "entity:name:<name>" → entity_id
- "entity:commit:<commit_id>" → [entity_ids]

Topic Keys:
- "topic:<id>" → Topic data
- "topic:category:<category>" → [topic_ids]
- "topic:keyword:<keyword>" → [topic_ids]

Relationship Keys:
- "relationship:<id>" → Relationship data
- "relationship:from:<entity_id>" → [rel_ids]
- "relationship:to:<entity_id>" → [rel_ids]
```

## Confidence Scoring and Validation

### Confidence Sources

1. **LLM Confidence**: Direct confidence from LLM extraction
2. **Structural Evidence**: Code parse confirmation
3. **Frequency**: Repeated mentions increase confidence
4. **Cross-Validation**: Multiple sources agreeing

### Scoring Algorithm

```rust
fn calculate_confidence(
    llm_confidence: f32,
    structural_evidence: bool,
    occurrence_count: u32,
    cross_validated: bool,
) -> f32 {
    let mut score = llm_confidence;

    // Boost for structural evidence
    if structural_evidence {
        score = (score * 0.7) + 0.3;
    }

    // Boost for frequency
    let freq_boost = (occurrence_count as f32).min(10.0) / 10.0;
    score = (score * 0.8) + (freq_boost * 0.2);

    // Boost for cross-validation
    if cross_validated {
        score = (score * 0.9) + 0.1;
    }

    score.min(1.0)
}
```

### Validation Rules

- Minimum confidence threshold: 0.5
- Low confidence entities marked for review
- Automatic validation against code structure when possible
- Manual curation interface for critical entities

## Plugin Implementation

### Plugin Structure

```rust
pub struct EntityExtractorPlugin {
    llm: Arc<dyn LlmProvider>,
    entity_cartridge: Arc<RwLock<EntityCartridge>>,
    topic_cartridge: Arc<RwLock<TopicCartridge>>,
    relationship_cartridge: Arc<RwLock<RelationshipCartridge>>,
    config: EntityExtractorConfig,
}

impl Plugin for EntityExtractorPlugin {
    fn name(&self) -> &str { "entity_extractor" }

    fn on_commit(&self, event: &CommitEvent) -> Result<()> {
        // Extract entities from mutation
        let entities = self.extract_entities(event)?;
        let topics = self.extract_topics(event)?;
        let relationships = self.extract_relationships(event)?;

        // Store in cartridges
        self.store_entities(entities)?;
        self.store_topics(topics)?;
        self.store_relationships(relationships)?;

        Ok(())
    }
}
```
