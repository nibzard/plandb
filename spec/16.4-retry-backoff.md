# Phase 16.4: Retry Logic with Exponential Backoff

**Status**: Implementation
**Owner**: Rust Implementation Team
**Start Date**: 2026-01-05

## Overview

This phase implements robust retry logic with exponential backoff for all cloud storage operations (S3, GCS, Azure). Retry logic is essential for handling transient failures in distributed systems, including network errors, rate limiting, and temporary service unavailability.

## Natural Language Description

### Retry Strategy

All cloud storage operations (upload, download, delete, exists, list) are automatically wrapped with retry logic. The retry strategy uses exponential backoff with full jitter to avoid thundering herd problems while providing fast recovery from transient failures.

### Key Principles

1. **Exponential Backoff**: Delay doubles with each retry attempt (base_delay * 2^attempt)
2. **Full Jitter**: Random delay in range [0, calculated_delay] to distribute retries
3. **Max Delay Caps**: Exponential backoff capped at max_delay to prevent excessive waits
4. **Retryable Errors**: Only retry transient errors (network, 5xx, throttling)
5. **Per-Operation Policies**: Different retry limits based on operation cost and idempotency
6. **Configurable**: All retry parameters configurable via RetryPolicy

### Exponential Backoff Algorithm

```
delay = min(base_delay * 2^attempt, max_delay)
actual_delay = random(0, delay)  // Full jitter
sleep(actual_delay)
```

**Example**: base_delay=100ms, max_delay=10s
- Attempt 0: delay = min(100ms * 1, 10s) = 100ms, sleep(random(0, 100ms))
- Attempt 1: delay = min(100ms * 2, 10s) = 200ms, sleep(random(0, 200ms))
- Attempt 2: delay = min(100ms * 4, 10s) = 400ms, sleep(random(0, 400ms))
- Attempt 3: delay = min(100ms * 8, 10s) = 800ms, sleep(random(0, 800ms))
- Attempt 6: delay = min(100ms * 64, 10s) = 6400ms, sleep(random(0, 6400ms))
- Attempt 7: delay = min(100ms * 128, 10s) = 10s, sleep(random(0, 10s))

### Retryable Error Detection

Errors are classified as retryable or non-retryable:

**Retryable Errors** (automatically retried):
- Network errors: connection refused, timeout, DNS resolution failure
- HTTP 5xx responses: 500 (Internal Server Error), 502 (Bad Gateway), 503 (Service Unavailable), 504 (Gateway Timeout)
- Rate limiting: 429 (Too Many Requests), S3 SlowDown, GCS 429
- Transport errors: connection reset, broken pipe
- Timeout errors: operation exceeded configured timeout

**Non-Retryable Errors** (fail immediately):
- Authentication failures: 401, 403 (credentials invalid, not transient)
- Not found errors: 404 (object missing, retrying won't help)
- Invalid request errors: 400 (malformed request, retrying won't fix)
- Permission denied: 403 (authorization failure, not transient)
- Checksum mismatch: data corruption (retrying with same data won't help)
- quota exceeded: hard limit (unless it's rate limit 429)

### Max Retry Attempts

Per-operation retry policies (default max_attempts):

| Operation    | Max Attempts | Rationale                                                                 |
|--------------|--------------|---------------------------------------------------------------------------|
| Upload       | 5            | Idempotent with same data, expensive to fail                              |
| Download     | 10           | Reads are safe to retry aggressively, data integrity critical              |
| Delete       | 3            | Eventually consistent, fewer retries to avoid cascading failures           |
| Exists       | 3            | Quick operation, fast fail preferred                                      |
| List         | 3            | Expensive operation, prefer fast fail                                     |
| Get Size     | 5            | Metadata read, moderately safe to retry                                   |

**Total Attempts** = max_attempts + 1 (initial attempt)

**Example**: Download with max_attempts=10 means up to 11 total attempts (1 initial + 10 retries)

### Per-Operation Retry Policies

Each operation type has a tuned RetryPolicy:

**UploadRetryPolicy** (5 attempts, 100ms base, 30s max):
- Lower max_attempts to avoid cascading upload failures
- Higher max_delay for large file uploads
- Moderate jitter to spread out retries

**DownloadRetryPolicy** (10 attempts, 100ms base, 30s max):
- Aggressive retries for data integrity
- Same delay parameters as upload
- Most tolerant policy (reads are safe)

**DeleteRetryPolicy** (3 attempts, 200ms base, 10s max):
- Conservative retries (eventually consistent)
- Higher base_delay (no rush on deletes)
- Lower max_delay (fail fast)

**MetadataRetryPolicy** (5 attempts, 100ms base, 10s max):
- Balanced policy for exists, get_size, list
- Moderate retries with fast fail

### Retry Policy Configuration

RetryPolicy is configurable:

```rust
pub struct RetryPolicy {
    pub max_attempts: usize,      // Maximum retry attempts (default: 5)
    pub base_delay: Duration,     // Initial delay (default: 100ms)
    pub max_delay: Duration,      // Maximum delay cap (default: 10s)
    pub jitter: bool,             // Enable full jitter (default: true)
}
```

**Predefined Policies**:
- `RetryPolicy::default()` → Generic policy (5 attempts, 100ms base, 10s max)
- `RetryPolicy::upload()` → Upload policy (5 attempts, 100ms base, 30s max)
- `RetryPolicy::download()` → Download policy (10 attempts, 100ms base, 30s max)
- `RetryPolicy::delete()` → Delete policy (3 attempts, 200ms base, 10s max)
- `RetryPolicy::metadata()` → Metadata policy (5 attempts, 100ms base, 10s max)

## Technical Design

### RetryPolicy Struct

```rust
use std::time::Duration;

/// Retry policy for cloud storage operations.
#[derive(Debug, Clone)]
pub struct RetryPolicy {
    /// Maximum number of retry attempts (excluding initial attempt).
    pub max_attempts: usize,
    /// Base delay before first retry (exponential backoff starts here).
    pub base_delay: Duration,
    /// Maximum delay cap (exponential backoff won't exceed this).
    pub max_delay: Duration,
    /// Enable full jitter to randomize delays (prevents thundering herd).
    pub jitter: bool,
}

impl RetryPolicy {
    /// Generic retry policy (5 attempts, 100ms base, 10s max).
    pub fn default() -> Self {
        Self {
            max_attempts: 5,
            base_delay: Duration::from_millis(100),
            max_delay: Duration::from_secs(10),
            jitter: true,
        }
    }

    /// Upload retry policy (5 attempts, 100ms base, 30s max).
    pub fn upload() -> Self {
        Self {
            max_attempts: 5,
            base_delay: Duration::from_millis(100),
            max_delay: Duration::from_secs(30),
            jitter: true,
        }
    }

    /// Download retry policy (10 attempts, 100ms base, 30s max).
    pub fn download() -> Self {
        Self {
            max_attempts: 10,
            base_delay: Duration::from_millis(100),
            max_delay: Duration::from_secs(30),
            jitter: true,
        }
    }

    /// Delete retry policy (3 attempts, 200ms base, 10s max).
    pub fn delete() -> Self {
        Self {
            max_attempts: 3,
            base_delay: Duration::from_millis(200),
            max_delay: Duration::from_secs(10),
            jitter: true,
        }
    }

    /// Metadata retry policy for exists/list/get_size (5 attempts, 100ms base, 10s max).
    pub fn metadata() -> Self {
        Self {
            max_attempts: 5,
            base_delay: Duration::from_millis(100),
            max_delay: Duration::from_secs(10),
            jitter: true,
        }
    }
}

### Error Classification

```rust
impl CloudError {
    /// Determine if this error is retryable.
    ///
    /// Retryable errors are transient failures that may succeed on retry:
    /// - Network errors (connection refused, timeout, DNS failure)
    /// - HTTP 5xx responses (internal server errors)
    /// - Rate limiting (429, SlowDown)
    /// - Timeouts
    ///
    /// Non-retryable errors are permanent failures:
    /// - Authentication failures (401, 403)
    /// - Not found (404)
    /// - Invalid request (400)
    /// - Checksum mismatch
    pub fn is_retryable(&self) -> bool {
        match self {
            // Network issues are retryable
            CloudError::NetworkError(_) => true,

            // Timeouts are retryable
            CloudError::Timeout(_) => true,

            // Quota exceeded is retryable only if it's rate limiting
            CloudError::QuotaExceeded(msg) => {
                let msg_lower = msg.to_lowercase();
                msg_lower.contains("rate limit") ||
                msg_lower.contains("throttle") ||
                msg_lower.contains("429") ||
                msg_lower.contains("slowdown")
            }

            // Generic errors may be retryable if they indicate transient issues
            CloudError::Other(msg) => {
                let msg_lower = msg.to_lowercase();
                msg_lower.contains("rate limit") ||
                msg_lower.contains("throttle") ||
                msg_lower.contains("5") ||  // 5xx errors
                msg_lower.contains("timeout") ||
                msg_lower.contains("connection")
            }

            // All other errors are not retryable
            _ => false,
        }
    }
}
```

### Retry Function

```rust
use tokio::time::sleep;
use rand::Rng;

/// Execute an async operation with retry logic.
///
/// # Arguments
///
/// * `operation` - Async operation to execute (returns Result<T, CloudError>)
/// * `policy` - Retry policy configuration
///
/// # Returns
///
/// * `Ok(T)` - Operation succeeded (possibly after retries)
/// * `Err(CloudError)` - Operation failed after all retry attempts
///
/// # Behavior
///
/// 1. Execute operation initially
/// 2. If operation fails with retryable error:
///    - Calculate delay using exponential backoff: `min(base_delay * 2^attempt, max_delay)`
///    - Apply full jitter: `random(0, delay)`
///    - Sleep for calculated delay
///    - Increment attempt counter
///    - Retry operation
/// 3. If operation fails with non-retryable error or max_attempts exceeded: return error
///
/// # Example
///
/// ```ignore
/// let policy = RetryPolicy::download();
/// let result = with_retry(|| async {
///     adapter.download("backup.nbk").await
/// }, &policy).await?;
/// ```
pub async fn with_retry<F, Fut, T>(
    operation: F,
    policy: &RetryPolicy,
) -> Result<T, CloudError>
where
    F: Fn() -> Fut,
    Fut: std::future::Future<Output = Result<T, CloudError>>,
{
    let mut attempt = 0;

    loop {
        // Attempt the operation
        match operation().await {
            Ok(result) => return Ok(result),

            Err(error) if error.is_retryable() && attempt < policy.max_attempts => {
                // Calculate delay with exponential backoff
                let exponential_delay = policy.base_delay * 2_u32.pow(attempt as u32);
                let capped_delay = exponential_delay.min(policy.max_delay);

                // Apply jitter if enabled
                let delay = if policy.jitter {
                    let mut rng = rand::thread_rng();
                    let delay_ms = capped_delay.as_millis() as u64;
                    Duration::from_millis(rng.gen_range(0..=delay_ms))
                } else {
                    capped_delay
                };

                tracing::info!(
                    attempt = attempt + 1,
                    max_attempts = policy.max_attempts + 1,
                    delay_ms = delay.as_millis(),
                    error = %error,
                    "Retryable error, retrying operation"
                );

                // Sleep before retry
                sleep(delay).await;

                attempt += 1;
            }

            Err(error) => {
                // Non-retryable error or max attempts exceeded
                tracing::error!(
                    attempt = attempt + 1,
                    max_attempts = policy.max_attempts + 1,
                    error = %error,
                    retryable = error.is_retryable(),
                    "Operation failed after retries"
                );
                return Err(error);
            }
        }
    }
}
```
